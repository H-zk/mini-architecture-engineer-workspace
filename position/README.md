# Position — 工作区定位基准

> 本文件是工作区的**定位基准**：我是谁、为什么存在、不做什么。**每次与外部对象对比、每次重大机制更新前先对照本文件**——发现偏移（借鉴会改变定位/初心）→ 停下评估、先过操作者裁决。定位变更仅由操作者定。

## 我是谁

1. **本质：人机协作工作区模板**——方法论与业务分离的脚手架：接入任意业务领域，按 SOP 快速上手、放大操作者产能；多实例之间互鉴产生演化。
2. **现状：单操作者实例**——架构工程师的工作区（业务领域见 [AGENTS](../AGENTS.md) 模板占位），承载需求开发、CASE 排查、技术咨询、需求调研、工作区迭代五类任务。
3. **形态：上下文工程（主体）**——编排是架构、上下文是运行时、提示词是源码：主体为上下文工程（管理什么信息进 AI 窗口、何时进），骨架为编排工程（状态机/门禁/标签分流，以「文档即程序、模型即解释器」实现），提示词工程为源码笔法层（AGENTS/WORKFLOW/skills 是载体语言）；分层判据见下方「形态判据」。与 BMAD、GSD 等开源方法论**形态相通、技法可交流，但本质不同**：它们是通用方法论产品；本模板是方法论的可复制脚手架——受让者的业务实例才是方法论的试验场，模板自身是中转与分发形态。

### 形态判据（2026-08-30 对齐源仓概念演进，操作者定）

从 AI 技术视角，本工作区不是单一学科，是三层叠加——**主体上下文工程、骨架编排工程、源码笔法层提示词工程**：

- **上下文工程（主体）**：管理「什么信息进 AI 窗口、何时进」——skills 语义命中才加载（渐进披露）、任务目录 CURRENT/README 是无状态会话的外置记忆、上下文洁净区、单一真源防膨胀（注意力去重）。
- **编排工程（骨架）**：Lifecycle 状态机、门禁绑定状态转移、标签分流——以「文档即程序、模型即解释器」实现（非代码引擎驱动）；代码强制的机器门禁（workspace-check `errors=0` 等）是从上下文工程长向编排工程的交界点。
- **提示词工程（源码）**：决定「一条指令怎么写得好」（角色/格式/优先级/few-shot），不决定「什么进窗口、流程怎么转」——是前两层的载体语言。

**判据（辨某机制属哪层，看它靠什么生效）**：靠「AI 读到文档并自觉遵守」→ 上下文工程；靠「代码强制执行」→ 编排工程硬边界。与外部库对比、机制演进评估时按此对号——防「提示词工程」旧称把评估引向纯措辞优化。

**演进的技术本质**：随人机分工演进（AI 自主性提升），会有一批机制从「靠 AI 自觉遵守」迁入「靠代码强制执行」（编排比重上升）——机制升级方向按此判读：能代码强制的逐步下沉机检，不留在自觉层。

## 初心（为什么存在）

1. **方法论可复制**：机制设计保持业务与方法论分离——业务知识进 `notes/`、业务代码仓进 `src/`（clone 集合，不进本仓 git），方法论进 WORKFLOW/skills/流程资产。
2. **业务落地为本**：业务任务是主业，治理（工作区优化）是手段不是目的。
3. **人机同行者，知识流双向**：人类给目标、做决策，AI 分析、执行，双方互相验证；知识不只沉淀给 AI 复用，也反哺操作者。
4. **经验是副产品**：任务收尾把可复用结论沉淀 `exps/`/`notes/`，让下次更快。

## 不变原则（重大更新不得偏移）

- **机制须被现实召唤**：宁可晚进、不早进——为不存在的需求建机制是过早优化。
- **单一真源 + 防膨胀**：机制细节一处真源，他处一句摘要 + 指针；顶层文档不承载任务产物。
- **业务 > 治理**：治理类任务占比持续超过业务类 = 偏移信号。
- **安全红线最高优先级**：上下文洁净区、凭证不读取不输出、生产边界（全文见 [AGENTS](../AGENTS.md)「安全红线」）。
- **代码为真**：知识库以文档为主（约 90% 可靠、随时间衰减）；涉「运行中系统当前如何」的事实判定，以 `src/` 所载仓库源码为准——文档与代码冲突时代码胜、修订文档（可靠性分层与冲突仲裁见 [WORKFLOW §5.1](../WORKFLOW.md)）。

## 边界（不做什么）

- 不追求通用 agent 框架的完备性——以「单操作者快速上手业务并放大产能」为目标复制，不为通用而通用、不为大而全堆机制。
- 不为对比而对比：外部借鉴先过「适配而非照搬」+ 本基准对照。
- 不脱离人机分工：AI 不取代操作者的方向裁决权。

## 对比体系（统一入口）

对比参照对象两类 + 记录一处，流程真源 [`colleague-kb-synthesis`](../.agents/skills/colleague-kb-synthesis/SKILL.md)：

- [colleague.md](./colleague.md) — **同事库/外部工作区**登记 + 同步记录（对比 = 工作流范式 + 知识侧重双维度）
- [open-source.md](./open-source.md) — **开源参照对象**登记 + 对比记录（锚定 latest stable release tag；对比 = 架构/范式单维度）
- [compare/](./compare/) — 每次对比记录，命名 `YYYY-MM-DD-vs-<对象>.md`
- **分层快照**（snapshots/ 实例不随产物分发）— 迭代边界版本锚：七层全景 + 数据画像，相邻快照章节级 diff = 版本差异通道；结构契约见 [retrospectives/snapshot-template.md](../retrospectives/snapshot-template.md)

**对比前**：同步最新仓库、锚定基线（同事库 pull/浅克隆 / 开源项目 release tag）。**对比后两轨分流**：需立即优化 → 建对应工作区任务；有价值待观察 → `BACKLOG.md`。
