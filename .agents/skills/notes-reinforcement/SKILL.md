# notes-reinforcement

> 本文是「知识库加固」维护项执行流的单一真源。notes 写入格式规范见 WORKFLOW §5.2；本流程强化（不取代）§2.4 沉淀归档。

## When（何时触发）

- `#workspace-optimize 知识库加固`，或 workspace-optimize 启动器选中「知识库加固」（第二步必填：已结 CASE/需求素材 + 查询入口）。
- 攒了一批已结 CASE/需求素材、想系统性补全业务链路知识时（按需，非固定周期）。

## 素材要求（Input）

- 来源**不限本工作区**：可以是其他人处理过的 CASE/需求。
- **CASE**：操作者告知结论详情的**查询入口**（地址/系统）；**需求**：操作者确认**已上线**（可回代码核实）。
- 素材入口形式决定走哪条路（见下「素材入口 vs 盲判可行性」）。

## Steps（5 步）

| 步骤 | 动作 | 产出 |
| ---- | ---- | ---- |
| ① 盲判 | 基于工作区现有内容（notes/exps/reference + 业务理解），独立判断触及哪条链路、产出「链路怎么走 + 关键决策点 + 可能的坑」。**不查结论入口**；不确定处显式标 `待核实` | 盲判方案（含盲点） |
| ② 方案 | 查 `notes/INDEX.md` 判**新增 vs 并入**（合并优先，WORKFLOW §2.4），输出沉淀方案（仍是盲的） | 沉淀方案（预览） |
| ③ 对照 | **此时才查**操作者给的结论入口 → 对照盲判方案，找**差异与遗漏** | 差异清单 |
| ④ 核实+沉淀 | 差异点和确认链路回 `src/` 代码核实（地面真相），按 WORKFLOW §5.2 写 notes | notes 条目（预览） |
| ⑤ 反思+去重 | 反思盲判里没想到的点（真正的坑/反直觉点）**优先记成 tips**；交叉检查既有 notes，合并重叠；更新 `notes/INDEX.md` | 更新 INDEX |

### 素材入口 vs 盲判可行性（① 前先分流）

「先盲判后对照」成立的前提是盲判阶段没看过结论。素材入口形式决定走哪条路：

- **纯盲判**（理想）：素材为口头/截图描述现象、或**未结 CASE**——独立产出链路方案后再对照；盲判暴露的盲点优先成坑（⑤ 的核心价值）。
- **验证型**（降级）：素材为**工单/已结 CASE 链接**——为判断主题/立项查询时不可避免看到完整结论，纯盲判前提被打破 → **跳过盲判，结论当待核实假设**，直接回 `src/` 代码逐条核实（纠偏工单可能的误记，如工单把问题产生位置记错服务层、或对某操作的作用范围记宽/记窄）。
- 两者均保留最高价值的「代码核实」一步；差别只在是否经历盲判。

### 对照补全（防单侧盲区，③ 之后）

单 CASE 素材易被「工单视角/单仓库」框定——工单常只记排查者触及的那一层（如只记接入层现象、漏掉背后多个服务协作）。沉淀后**主动检索工作区内外有无同源排查记录**（`notes/`、`exps/` 关键词检索；操作者若可提供他人排查材料则对照）；他人若是第一手排查者，其沉淀常覆盖更全链路；发现盲区后**回 `src/` 代码核实补全**（非照搬他人结论）。

### 自我判断始终在线（验证型/对照 ≠ 找印证）

无论纯盲判、验证型还是对照补全，回 `src/` 核实的姿态都是**独立审视**，不是「找代码印证结论」。工单/他人结论都是**待检验假设**——可能错（记错位置、记错作用范围），也可能**片面**（只记单一服务层、漏掉跨服务协作面）。核实时主动问：这结论对吗？全不全？有没有它没提到的面或反例？**代码是地面真相，结论服从代码，不是代码服从结论。**

## Gates

- **不偷看答案**：① 盲判阶段严禁查结论入口（验证型除外——前提已破，如实标注走降级路径）。
- ②④ **先预览、操作者确认后写入**（notes 虽为 Agent 可写，批量产出更需一致性确认）。
- 一切结论（工单/他人/盲判）一律经 `src/` 代码核实才落 notes。

## 沉淀原则（notes 是代码的路标，不穷举实现）

1. **业务链路**：mermaid 数据流/时序图讲清「数据从哪来、经谁处理、到哪去」。
2. **数据上下游**：写清写入方/读取方/触发条件/时效。
3. **关键坑（tips）**：易错决策点一句话点透、不展开实现；**盲判对照暴露的盲点优先成坑**。
4. **代码位置**：关键论断附 `file_path:line` 便于下钻；不记易变实现细节（见 WORKFLOW §5.2）。
5. **单处定义**：每个概念只在一处定义、跨文档用链接引用；既有 notes 已覆盖的，并入而非新建。

## Outputs

- notes 条目（新增或并入）+ `notes/INDEX.md` 更新；过程留任务目录（`README.md` + `CURRENT.md`）。
- 无代码交付；Lifecycle 由 workspace-ops 两态承载（`#workspace-optimize`）。

## Verify

- 写入后跑 `python .tools/workspace-check.py --task <当前任务>`（errors=0）。
- 交叉检查：新 notes 与既有条目无概念重复定义。
