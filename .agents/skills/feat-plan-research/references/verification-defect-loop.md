# 验证期缺陷修复循环（代码先行定位 + 假设日志一轮证 + 对照环境）

> 解决的真实痛点：验证中阶段的 AI 自动化验证又慢又脆——环境装配反复、交互模拟踩坑、**把环境问题读成代码缺陷**、以及「看页面反馈再决定下一步」的试错循环。本文件管「验证中缺陷单 → 定位 → 修复 → 验证 → 交付人眼」这一段循环的**排序**；问题登记与出路分级（补丁级/实现级/计划级）走 skill 验证中节，跨环境排查（线上异常、无缺陷单）走 CASE 排查流。

## 七步（顺序本身就是成本控制）

1. **基座同步 + 环境重建**：fetch → 合并最新开发线（已推 feature 走 `merge origin/<开发分支>`，未推可 stash→merge→pop 保未提交改动）→ 按仓库 lockfile 形态选 `npm ci` / `pnpm install --frozen-lockfile` 装依赖（勿跨制混装）→ 构建产物 → 起 dev server（显式确认 BUILD_ENV 一类环境开关）→ 数据源/预置内容前置 → 注入类前置（SW 等）。
2. **环境冒烟（不带病排查）**：页面可进 + 数据正常 + 无新增 fatal 报错。**冒烟不过先修环境**——本步是后面所有结论的地基。
3. **代码先行定位（最关键的一步，省掉最多运行时试错）**：读源码把假设闭环到**「事实」级**——不止「疑似命令空发」，而是「命令 A 的消费者 = 组件 S，某模式下 S 不创建 → A 在该模式无消费者」。链上每一跳都点名生产方/消费方在该模式下的存在性，能静态定死就静态定死。
4. **假设性日志打点**：按第 3 步的链在关键节点（入口 / 分支判定 / 结果发射 / 回传）打临时日志——统一可 grep 前缀 + 注释声明「验证后清理」。日志让运行时自证，而不是靠人隔着 UI 猜。
5. **一次自动化跑完整链断言**：驱动优先内部句柄/API（薄可控），真实 UI 路径作补充；断言 = **日志链 + 网络证据（URL/状态码）+ 状态流转**三分位，**不依赖画面识别**；同轮跑**官方环境对照**（发布版、非改造形态）确认「期望形态」长什么样。
6. **清理日志 → 重建 → 交付**：grep 前缀清零 + lint 0 + 重新构建并同步产物；构建副产物按仓库纪律还原（`git checkout -- dist/` 类）。
7. **人眼验收（交付指引必须自包含）**：给操作者的链接 + **全部环境前置步骤**（注入命令、URL 参数、登录路径）一并给出——缺前置 = 对方看到假阴性。

## 三类「假阴性」：验证结论不可信的最常见来源

| 来源 | 典型形态 | 识别 |
| ---- | ---- | ---- |
| 载体能力退化 | 自动化浏览器升级丢某渲染能力 → 画面断言全红 | 跑**纯文件基线**（本地静态产物直接渲染）定载体能力 |
| 前置未注入 | SW/开关/参数没生效 → 未发布修复表现为「无效」 | 核实**实际加载的资源 URL/版本**，不是配置意图 |
| 供给/数据态陈旧 | 数据源仍发旧版本内容 → 与被测代码无关的假红 | 抓实际数据 id/时间戳与本次会话时窗对不上 |

统一判别动作：**「换官方环境 / 换载体，现象还在吗」**——A/B 是性价比最高的排除法；能力探测类 API、状态接口字段一类「声明式信号」一律不当能力/事实依据。

## 边界

- **画面级判定归人眼**：自动化载体不保证媒体栈能力；能闭环的部分（命令链/网络/状态）就闭环，别为凑画面把循环拖长。
- **修复前先证假设**（第 3–4 步），修复后**一次**跑完整链（第 5 步）——避免「改一点看一眼」的多轮往返。
- **验收标准是修复优先级的裁决器**：契约违约但验收无求（demand/验收口径零覆盖）→ 留档不修，不为契约完整性无限投入——联调发现的问题先查验收标准再定处置。
