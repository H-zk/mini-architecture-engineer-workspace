# 设计对照与组件选型模板（plan.md「设计对照」节）

> 仅用于「UI 涉及 且 有设计稿/原型/demo 输入」的 feat 任务写 plan 时；无设计输入的 UI 需求不适用。产出物落该任务 plan.md 的「设计对照」节，本文件只承载结构与纪律、不承载具体映射。组件约束真源 = 目标仓 `AGENTS.md`（不建影子规范）。
> provenance：基于 v1 sprint-20260827 提炼（tag c199e14），脱敏重写、示例通用化。

## 结构（复制进 plan.md 后填充）

### 输入指针

- 设计稿：【模板占位：链接/路径】
- demo / 原型：【模板占位：路径或仓】
- 组件约束真源：目标仓 `AGENTS.md`（组件库、封装约定）

### 组件映射表

| 设计区域/帧 | demo 实现方式 | 目标仓组件 | 原生/缺口 | 备注（差异与取舍） |
| ----------- | ------------ | ---------- | --------- | ----------------- |

### 组件库缺口处置（缺口 ≠ 顺手造组件）

每处缺口三选一**经操作者确认**，不静默决定：

1. 现有组件近似替代（记录差异与取舍进备注列）；
2. 原生实现（一次性、无复用价值时）；
3. 补组件库（进库仓 = **另立任务/子项**，主任务只做接线——防 scope 蔓延）。

### 对照口径

- demo 是**结构级对照基准**（布局结构/信息层级/文案）；
- **像素级对齐以设计稿标注为准**。

## 纪律

1. 冲突优先级：`设计标注 > demo 结构 > 库默认形态`——冲突项逐条登记备注列，不静默按库默认走。
2. 缺口处置项未经操作者确认不进编码。
3. 映射表随 plan 一并过执行门禁（操作者确认 plan 即确认选型，不单独多一轮）。

> 反例模式（源仓实测）：跳过映射表直接编码 → 组件选型大面积返工（还原度评分近乎腰斩）。
