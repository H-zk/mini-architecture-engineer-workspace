# 注释清扫与精简判据细则

> 门禁时机、清扫范围、召回 grep 模式与放行流程在 SKILL「推送前注释清扫门禁」节；本文件承载逐处判断的**判据细则**。统一判据（SKILL 已摘要）：**这行注释对「没有本任务上下文的维护者」是否正向获益**——不是「是否复述代码字面」。

## 统一判据展开

- 判据一旦错位成「复述代码 = 冗余」，会成批误删两类真资产：**英文标识符 + 中文短标签**（`// 已上架`、`<!-- 仅管理员可见 -->`——维护者不读代码即扫懂业务分支，这是快扫价值不是复述）、**同族字段的 JSDoc**（邻居字段全带 JSDoc 时，裸字段反而突兀）。
- 反向也要治：**过长注释是负资产**——连排大段让维护者只读出「这里有复杂麻烦的逻辑」，认知负担反升。目标不是「删得多」而是「读起来省力」：短标签留、长篇压到只剩约束句。
- 二者的分界看**信息是否只服务于当下**：短标签服务于后续任何读者（留）；叙述性措辞只服务于当时的写作过程（删）。

## 约束句须自包含（只写禁令不算合格）

「不要加 X」只交付了一半——缺了「加了会怎样」，维护者无法判断哪些改动安全。

- **自造术语不算自包含**：任务临时造的词（如 `z-clean`、`单平面化`、`死值` 这类），即使句子很短也不合格——解码成本转嫁给了读者。改成「约束 + 具体后果」（如「勿加 z-index / transform：会创建层叠上下文，且 transform 使定位后代以该元素为基准而非视口」）。
- **术语可用的条件**：仓库内有唯一定义处且注释指得到（术语 + 指针合格，指针指向的 README 必须真实存在）。
- **同一机制只用一种叫法**：同一层叠机制在库内同时叫两个名字，维护者会以为是两回事。
- **同一术语被扩用到多个指称时收敛**：判法 = 先查该词在基线的既定指称，有则新用法换词或显式限定（如「宿主元素」「所在容器」），别让一个词承担多义。
- **集合代称须有代码结构对应物**：代称能对上某组成员、层目录、提示条组，合格；对不上任何结构——改成直说作用对象。判法：拿不准就去仓库里找这个集合的成员清单，找不到就是自造集合。
- **交付给外部的包（SDK / 组件库）里不出现任务自造词**：判法 = 该词在包基线（含 README）里有无命中，零命中即自造；处置 = 换自包含表述，或指向包内真源符号。同款重复尾标签（同一括号注释贴 N 次）收敛为**一处分组注**。

## 识别信号与收口纪律

- **恢复量 ≈ 删除量 = 判据没定准**：一轮清扫后出现「删了 N 处又几乎全数恢复」的来回，说明判据未一次定准——停下重定判据，不靠加轮次补救。
- **判据在动第一处前定准**，不在清扫过程中边删边改口径（注释遍布全仓，判据松紧一变，代价是全部相关文件重回 diff）。
- **注释改动走独立的隔离评审轮一次性收口**，不混在编码期顺手做——编码期顺手的判据受「当下主线」语境牵引，容易偏向「删」。

## 清除类与精简类

**清除**：决策/过程锚点（轮次号、决策号、子任务号、任务文档名——有长期价值的约束改写为自包含后保留语义）；过程性措辞（「（联调实测）」类只在任务过程语境可解的限定——删或改自包含）。单号（工单/需求单号）按 SKILL 门禁口径处理——外部持久单号允许保留，commit message 单号另循仓规范。

**精简**：重复说明去重（多处重复同一句 → 全删或收敛一处）；自明注释删（按统一判据——删掉后无任务上下文的维护者是否仍能读懂）；多行 JSDoc 收敛单行（信息密度撑不起多行时；`@param` 罗列型、踩坑机制型保留多行）；头部块注释收敛到 1–2 行。

**保留判据（防误删）**：统一判据优先，本节各条是它的场景化展开；仓内先例（grep 相邻同款——有先例即保留，不因「看起来冗」而清）；知识密度合格（踩坑结论、口径约束、机制取舍——保留，措辞可收敛）；项目规范形态（`@file` 首行等仓要求形态——保留形态、只清内容里的锚点/单号）。

## 收口三件套（注释类改动的标配终检，零外部依赖）

1. **术语频率审计**：任务新增注释的高频中文词（≥5 次）逐个对照 merge-base 基线 grep——零命中的按锚点判据逐个判（有定义处/README 指针/描述性词 → 合法；否则改写）；多义词（基线已定义指称、任务又扩用他义）在此步现形。
2. **幽灵符号扫**：注释里的大写 token / 桥接函数名全量对照源码存在性——零命中即注释指认了不存在的符号。事实漂移的主要来源之一。
3. **机械残渣扫**：批量替换后必跑——空括号、双标点、悬空左括号、星号后双空格（多为前几轮脚本替换自产碎屑）。

**事实漂移三来源**（注释审读时优先核这三类断言）：① 幽灵事件/符号（注释指认的东西不存在或零消费）；② 架构迁移后旧断言未随行更新（「仅用来展示」——按钮后来绑了事件）；③ 绝对化/单端表述被证伪（「全部」「唯一」「移动端」——实为双端共用）。
