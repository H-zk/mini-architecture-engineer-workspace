# 契约快照模板（design.md「契约快照」节）

> 仅用于「规格判定为大需求 且 涉及跨端/跨仓接口/事件契约」的 feat 产出契约快照；常规需求不适用。产出物落该任务 design.md 的「契约快照」节，本文件只承载结构与纪律、不承载具体契约。

## 结构（复制进 design.md 后填充）

### 契约快照

#### 接口 / 事件清单

| 接口/事件 | 方向（上报/拉取/下发） | 消费方仓库 | 契约源（后端定义/工单/既有实现） | 状态（已确认/待确认） |
| --------- | -------------------- | ---------- | ------------------------------ | ------------------- |

#### 字段明细（字段 + 传参方式 + 值域——缺一不算冻结）

| 字段 | 传参方式（body/query/字段层级/事件 payload 路径） | 值域（枚举值/格式/单位/空值语义） | 消费方 | 待确认点 |
| ---- | ---------------------------------------------- | ------------------------------ | ------ | ------- |

#### 五轴冻结清单（任一轴空缺 = 该接口快照未冻结）

| 轴 | 必答内容 | 典型爆点（缺轴会怎么炸） |
| -- | -------- | ------------------------ |
| 信封结构 | 成功码值域（200？0？）、分页包裹层级与键名（data 内层还是顶层兄弟）、错误体形状 | 「另返回 count」没定层级 → 联调才发现 count 在 data 内层；跨系统成功码不同 → 过滤器掉异常 |
| 请求参数全集 | 每接口查询/路径/体参数全集，含鉴权与归属参数（account_id 类）；参数值的构造规则（前缀映射、id 拼接类）显式给出 | 漏列归属参数 → 后端必填校验联调才拒；值构造规则没约 → 两端各拼各的、对不上被拒 |
| 值形态 | 时间序列化格式（ISO `T` 还是空格分隔、时区、序列化框架 naive/aware 配置）、金额单位、空值语义 | 「标准日期时间」无格式 → 前端裸显 ISO 原串 |
| 枚举值域全列 | 状态枚举之外的一切派生枚举（事件类型、流转类型等）逐个列出**实际值**，不写「同状态枚举」类引用 | 漏事件类型枚举 → 前端映射表按想象建、几乎全不命中 |
| 鉴权与路由归属 | 端点直连还是经网关/代理；身份从哪来（请求头/参数/服务端代取） | 「沿用 XX 约定」式引用悬空；架构改道（换代理路径）后契约零回写、下游跟着猜 |

#### 值正确性必答项（值对不对，独立于形态对不对）

- 每个枚举值/渠道码/类型码与**需求原文**、**既有系统字典**（领域字典表、管理后台下拉、模型 choices）逐一对齐后再冻结——前端命名是线索不是结论（字面直觉 ≠ 领域编码既定语义，需求圈定的名称与系统编码可能不是同一对）。

#### 细节点确认清单

- 逐条列「容易各说各话」的细节（命名风格、时间单位、空值语义、编码、时区、大小写敏感…），每条标已确认 / 待确认——待确认项非空 = 快照未冻结，进 plan 待确认问操作者。

## 纪律

- **快照随 plan 过执行门禁一并确认**——操作者确认 plan 即确认快照，不单独多一轮。
- **契约表述必须可执行检验**：「至少包括」式清单（字段名与形态不定）、「沿用 XX 约定」式引用（沿用值无人核对）、「标准 XX」式形容（无标准可依）是三类歧义温床——歧义处逐个替换为字段名 + 形态 + 值域的白纸黑字再冻结。
- **契约管数据结构，展示格式化是前端职责**：「按后端返回值展示」类字面把格式化责任甩进契约——两层各归其位，别互相甩。
- **开放问题闭环**：快照冻结时开放问题区逐条闭环；确需挂起的 → 显式转为联调检查点清单（进 plan）并知会契约 owner——**挂起 ≠ 解决**，deferred 的开放问题没有联调启动前强制闭环，就是排期的爆点；交付（转 `审核中`）前复核一遍全部闭环或转检查点。
- **联调偏差当轮处置**：联调期发现实现偏离契约 → 当轮登记（verify-issues 类目）+ 当轮知会契约 owner（评审/契约发起方）；架构改道同此——发现方登记与知会，契约回写归 owner，不等收尾。
- **契约变更 = demand.md「变更记录」追加行 + 强制附影响面评估行（几仓几文件）**，无评估不算合法变更——防「变一次口径、多仓联动返工」。
- 反例模式（粒度为什么卡在五轴）：字段名对齐了但**传参方式**没确认 → 返工；**值域**没对齐 → 值传错；信封/枚举/路由任一轴空缺 → 联调期才互相发现各说各话——只列字段名清单不算契约冻结。
- **联调问题四类归因，主体是粒度不足**：明确违约 / 约定歧义 / 契约空白 / 范围外——契约粒度不足以守而非谁不守约，冻结质量值得多投入。
