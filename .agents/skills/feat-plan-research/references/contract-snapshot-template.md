# 契约快照模板（design.md「契约快照」节）

> 仅用于「规格判定为大需求 且 涉及跨端/跨仓接口/事件契约」的 feat 产出契约快照；常规需求不适用。产出物落该任务 design.md 的「契约快照」节，本文件只承载结构与纪律、不承载具体契约。

## 结构（复制进 design.md 后填充）

### 契约快照

#### 接口 / 事件清单

| 接口/事件 | 方向（上报/拉取/下发） | 消费方仓库 | 契约源（后端定义/工单/既有实现） | 状态（已确认/待确认） |
| --------- | -------------------- | ---------- | ------------------------------ | ------------------- |

#### 字段明细（三要素：字段 + 传参方式 + 值域枚举——缺一不算冻结）

| 字段 | 传参方式（body/query/字段层级/事件 payload 路径） | 值域（枚举值/格式/单位/空值语义） | 消费方 | 待确认点 |
| ---- | ---------------------------------------------- | ------------------------------ | ------ | ------- |

#### 细节点确认清单

- 逐条列「容易各说各话」的细节（命名风格、时间单位、空值语义、编码、时区、大小写敏感…），每条标已确认 / 待确认——待确认项非空 = 快照未冻结，进 plan 待确认问操作者。

## 纪律

- **快照随 plan 过执行门禁一并确认**——操作者确认 plan 即确认快照，不单独多一轮。
- **契约变更 = demand.md「变更记录」追加行 + 强制附影响面评估行（几仓几文件）**，无评估不算合法变更——防「变一次口径、多仓联动返工」。
- 反例模式（粒度为什么卡到三要素）：字段名对齐了但**传参方式**没确认 → 返工；**值域**没对齐 → 值传错——所以只列字段名清单不算契约冻结。
