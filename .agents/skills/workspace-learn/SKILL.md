# workspace-learn

> 本文是「外部工作区学习沉淀」协议的单一真源：主动学习一个**有演进历史**的外部工作区（实战/同事工作区），沿证据链提炼可借鉴机制，产出分优先级借鉴清单——**只分析不自动落实**，操作者逐条裁决后才动真源。落位 [GUIDE §3](../../../GUIDE.md)「学习与扩展能力」（原「同事库对比」扩展位的通用化落地）；任务由 `#workspace-optimize` 承载（Lifecycle 见 workspace-ops），本 skill 不建独立状态机。

## When（何时触发）

- 操作者要求学习/对比/借鉴某个外部工作区：「学习一下这个实战工作区」「对比下我们和同事库的差别」「看看他们工作区有哪些值得借鉴的」「把同事库对比跑一遍」（末者常经 workspace-ops 维护菜单进入）。
- 前提：外部工作区**有演进历史**（CHANGELOG + 任务目录）——证据链是本 skill 的立足点；无历史的静态仓库或文章只能做无证据提炼，不适用本 skill。
- 边界：审计**自身**工作流走 workspace-grill，review 本仓未提交改动走 workspace-review——均不涉及外部学习源，勿混。

## 授权前提（先于一切外部访问）

- **路径即授权范围**：外部工作区路径由操作者**明确给出** = 对该路径的**只读**授权（呼应 [AGENTS](../../../AGENTS.md)「安全红线」：默认禁外部、经授权临时放开）；该路径之外的外部访问仍默认禁止。
- **只读不写**：不修改、不 commit、不在外部路径产生任何文件（临时分析产物落自身任务目录或 `temp/`）。
- **密钥载体绝不读取**：外部 `.env.local`、`.env` 及任何疑似凭证/密钥文件直接跳过——外部密钥既不读取也不加载。
- **不动远端**：默认读操作者给出的本地副本，不 clone、不 fetch/pull；确需同步最新 → 请操作者完成或明确授权后仅做只读获取，落点由操作者指定，绝不 push。

## Why

外部工作区与「读一篇好文章」的本质差别是**有演进证据链**：CHANGELOG 记录机制被反复修正打磨、任务目录记录机制被真实使用——据此能区分「已定型机制」与「纸面设计/试行期试验」，这正是反哺判据「只带已定型、业务中立机制，试行期不带」（CHANGELOG v0.8）的来源。同时，一次性照搬一批机制极易「为不存在的需求建机制」（见 [BACKLOG](../../../BACKLOG.md)「为什么有这个文件」）；沉淀又须**来源中立**（[WORKFLOW §4.2](../../../WORKFLOW.md)：外部只是提炼原料，不是长期引用来源）——三者共同决定了本 skill 的形态：带证据地提炼、只分析不落实、裁决后默认先进 BACKLOG。

## Steps（操作流）

1. **定边界 + 建自身基线**：向操作者确认学习目标（全量 / 聚焦维度，如「只看知识组织」）；读自身热层建立现状基线——WORKFLOW、各根目录与 `.agents/skills`/`.tools` 的 INDEX、CHANGELOG 首条版本基线。先知道自己有什么，每条候选才有「他有我无 / 我有他优 / 双方等价」的判定基准。

2. **外部扫描**（先索引后正文，遵守 [WORKFLOW §2.2](../../../WORKFLOW.md) 读取纪律）：

   - 入口文档（README/AGENTS/WORKFLOW 类）→ 目录结构（各根目录 INDEX）。
   - **锚定基线**：对方是 git 仓库则记当前 HEAD commit（后续复对比可判定增量）；本地副本记目录现状。报告中的证据均相对该基线。
   - **演进证据链（本 skill 与无历史提炼的本质差异）**：CHANGELOG 读版本演进（首条 + 与候选机制相关条目，不全文通读）；任务目录（README/CURRENT）看活跃与历史任务。
   - 重点识别**哪些机制被真实使用反复需要**：有多次触发记录、被多次修正打磨 = 已定型；只在规则文档里出现、任务历史找不到使用痕迹 = 纸面设计/试行期。

3. **双维度对比**（对照第 1 步基线）：

   - **工作流范式**：任务流转 / 状态机 / 门禁 / 目录职责划分。
   - **知识组织**：exps/notes/skills/tools 的准入、索引、毕业（有进有出）机制。

4. **产出借鉴清单（`learn-report.md`）**：每条 = 机制观察 + **外部演进证据**（哪些 CHANGELOG 条目/任务记录佐证）+ 与自身差异 + 采纳价值（高/中/低）+ 落地成本（高/中/低）+ 建议（直接落地 / 进 BACKLOG / 不采纳）。**只分析不自动落实**——清单连同证据交操作者裁决，不动任何真源。

5. **裁决分流（操作者逐条裁决后执行）**：

   - 落地 → 本 `#workspace-optimize` 任务承载（同主题连续工作 = 增项，不立新 task）。
   - 进 BACKLOG → 登记「做法 + 为什么暂不纳入 + 触发信号（含阈值）」。
   - 不采纳 → learn-report 结论留一句理由即可。
   - 落地写入仍过目标真源各自的写入纪律（门禁见下）；软链：一轮学习跑完建议接一次 workspace-grill（BACKLOG 唯一评估入口）。

## Gates（门禁）

**借鉴清单交付前、裁决后落真源前，逐条过检**：

- **锚定基线**：对比前先锚定对象基线（git 仓库记 HEAD commit、开源项目记 release tag），证据与结论相对基线成立；无锚定的对比结论不可信。
- **来源中立**（WORKFLOW §4.2）：沉淀物不点名外部、不把外部文件作长期引用；判据——「去掉外部引用，这条沉淀还成立吗」不成立就先转换再说。
- **中立化转换**：外部业务措辞（业务域/工具/目录语义）转通用表述、可变点标 `【模板占位】` 才可入真源；公司名/产品名/人名一律剥离。
- **已定型判据**（v0.8 教训）：外部仍在试行、无多次使用证据的机制不直接带入 WORKFLOW/skill——最多进 BACKLOG 观察位。
- **宁可晚进**：候选默认先进 BACKLOG 等真实使用召唤；「直接落地」仅限操作者逐条裁决确认的条目，不批量打包采纳。
- **防重复**：每条先查自身是否已有等价机制（grep 相关 INDEX/真源）；有等价 → 评估合并增强，能合并则不新增平行机制。
- **认知护栏**：grep 零结果只能表述为「当前搜索范围内未观察到」，不得下「外部没有 X / 这是他们独有」的断言。

## Outputs（产物与去向）

- **分析产物**：`workspace-optimize/task-<日期>-learn-<对象>/learn-report.md`（借鉴清单，含证据与逐条裁决结果，留任务目录）。
- **沉淀物（裁决后）按性质落真源**：机制 → WORKFLOW/对应 skill；经验 → `exps/`（来源标 `[external:<通用名>]`）；知识 → `notes/`；候选 → BACKLOG。落真源时过中立化 + 防重复门禁，改带 frontmatter 的文档同步 bump `updated-at`。
- **无独立状态机**：本 skill 由 `#workspace-optimize` 任务承载（两态 Lifecycle 见 workspace-ops），本文件 frontmatter 不设 `states:`。
