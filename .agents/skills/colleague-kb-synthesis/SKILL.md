# colleague-kb-synthesis

> 两个知识库/工作区「对比分析 → 借鉴清单」的**通用方法论**。对比对象分两类：**同事库/外部工作区**（工作流范式 + 知识侧重双维度）与**开源参照项目**（聚焦架构/范式单维度）。**仅分析、不自动落实，且不预设结论**——所有对比发现必须来自真实读取双方内容。任务由 `#workspace-optimize` 承载（Lifecycle 见 [workspace-ops](../workspace-ops/SKILL.md)），不建独立状态机。

## When（何时触发）

- 操作者说「对比一下 A 库和 B 库 / 看看 X 工作区有什么值得学 / 对比一下 XX 开源项目」（常经 workspace-ops 维护菜单进入）。
- 同步了 `position/` 某个登记对象后，主动提议做一次系统对比。
- **一次性对象（临时授权模式）**：操作者本轮给出一个未登记的外部工作区本地路径 = 临时只读授权——对比记录落任务目录 `learn-report.md`，是否登记 `position/` 事后裁决。
- 前提：同事库类对象**有演进历史**（CHANGELOG + 任务目录）——证据链是判「已定型」的立足点；无历史的静态仓库或文章只能做无证据提炼，结论一律降级标注。
- 边界：审计**自身**工作流走 workspace-grill，review 本仓未提交改动走 workspace-review——均不涉及外部学习源，勿混。

## 授权前提（先于一切外部访问）

- **路径即授权范围**：外部路径由操作者**明确给出** = 对该路径的**只读**授权（呼应 [AGENTS](../../../AGENTS.md)「安全红线」：默认禁外部、经授权临时放开）；该路径之外的外部访问仍默认禁止。
- **只读不写**：不修改、不 commit、不在外部路径产生任何文件（临时分析产物落自身任务目录或 `temp/`）。
- **密钥载体绝不读取**：外部 `.env.local`、`.env` 及任何疑似凭证/密钥文件直接跳过——外部密钥既不读取也不加载。
- **远端动作经授权**：默认读本地副本；登记对象的同步按 [position/colleague.md](../../../position/colleague.md) / [position/open-source.md](../../../position/open-source.md)「取数方式」执行（浅克隆到 `temp/` 下临时目录，用完即清），绝不 push。

## Why

外部知识库/工作区各自沉淀了不同的成熟实践，但**对比时易凭印象、维度不一**（有时只看流程、有时只看内容，遗漏结构性缺口），**借鉴时易照搬不适配的机制**（定位/规模/职责差异），且**双份维护是负担**。同时外部工作区与「读一篇好文章」的本质差别是**有演进证据链**：CHANGELOG 记录机制被反复修正打磨、任务目录记录机制被真实使用——据此区分「已定型机制」与「纸面设计/试行期试验」，防止把试行态当成熟经验带入；一次性照搬一批机制又极易「为不存在的需求建机制」。本 skill 把「同步锚定 → 基准对照 → 系统对比 → 真实读取 → 筛高价值 → 适配而非照搬 → 裁决分流」流程化，且沉淀须**来源中立**（外部只是提炼原料，不是长期引用来源）。

## Steps（对比分析流程）

> **总原则**：以下维度是「建议对比哪些方面」，**不是结论模板**。每个发现都要能指向**真实读到的双方内容**，不预设、不凭印象、不照抄某次对比的结论。

0. **同步前置（铁律）——对比前先同步最新，对比记录锚定版本与 commit**：
   - **登记的同事库**：按 [position/colleague.md](../../../position/colleague.md) 同步流程拉取/浅克隆，同步动作留痕其「同步记录」表。
   - **登记的开源项目**：按 [position/open-source.md](../../../position/open-source.md)「取数方式」浅克隆（`temp/` 下临时目录），**基线锚定最新 stable release tag**（排除 rc/beta 预发布；`git fetch --depth 1 origin tag <tag>` 后 checkout），**不用分支 HEAD**。
   - **一次性对象**：本地副本即基线（git 仓库记当前 HEAD commit）。
   - 记录对比基线：**仓库 + 版本（tag，开源项目）/ 分支（同事库）+ commit（短）+ 日期**，写入对比记录头部——结论只对该基线负责。
   - **基准对照**：读 [position/README.md](../../../position/README.md)（工作区定位基准）——对比发现与借鉴建议均以此为锚；借鉴点若会改变定位/初心（偏移信号）→ 单独标注交操作者裁决，不混入常规清单。
   - **对比模式判定**：先查该对象的上次对比（position 两登记文件记录表 + [compare/](../../../position/compare/) 既有档案）——距上次 ≤1 个迭代且有档 → **增量模式**（只比上次基线以来的新变更，既有结论引用不重做）；间隔更久、无档案、或对方发生结构性变更 → **全量模式**。
1. **读双方入口与索引 + 建自身基线（先 index 后正文，防上下文膨胀）**：
   - 自身基线：WORKFLOW、各根目录与 `.agents/skills`/`.tools` 的 INDEX、CHANGELOG 首条版本基线——先知道自己有什么，每条候选才有「他有我无 / 我有他优 / 双方等价」的判定基准。
   - 逐一定位双方入口文件（`AGENTS.md`/`README.md`/`WORKFLOW.md` 类）+ 各内容目录检索索引；不通读全文，命中再读正文结论段；深度对比用 subagent 并行深挖，避免主上下文膨胀。
   - **演进证据链**：CHANGELOG 读版本演进（首条 + 与候选机制相关条目）；任务目录（README/CURRENT）看使用痕迹——有多次触发、被多次修正打磨 = 已定型；只在规则文档里出现、任务历史找不到使用痕迹 = 纸面设计/试行期。
2. **工作流范式对比（第一维度，所有对象必跑）**——按建议维度逐项比对落差异表（维度可按实际增减）：组织主轴（按任务/时间 vs 按知识/主题）、任务/流程管理、真源观念（什么被视为权威、冲突怎么仲裁）、代码与提交策略、技能/规则加载机制、防膨胀/可发现机制、沉淀触发与时机、安全/边界约定；**开源项目加深化视角（提示词工程技法）**：persona/角色定义、门禁与状态机写法、提示词资产结构与复用、上下文管理策略。产出一句话定性双方范式差异。
3. **知识/内容侧重对比（第二维度，仅同事库）**——读各索引统计内容分布：内容类型分布与体量侧重、抽象层级（元层「怎么干」vs 领域层「干什么」）、覆盖广度与深度；产出双方知识重心定性 + 分布表。**开源项目跳过**（无业务重叠）。
4. **识别缺口与可借鉴点，分两类整理**（具体项由实际对比得出，不预设）：
   - **治理方法论类**：工作区如何被治理、如何防失效、如何沉淀——以实际读到的为准。
   - **业务内容类**（仅同事库）：对方有而已方缺的业务知识/地图/盲点。
   - 每条标注：**借鉴点 → 己方缺口 → 适配注意**（注意双方定位/规模/职责差异，适配而非照搬）。
5. **按优先级产出借鉴清单**：🔴 P0 结构性缺口（不补会出大问题）；🟡 P1 具体盲点（低成本增量补齐）；🟢 P2 治理增强（锦上添花）。
6. **来源中立标注 + 对比记录落档 + 两轨分流**：
   - 每条借鉴点过判据「去掉对另一库的引用是否仍成立」→ 成立才收录；来源标注：同事库 `[colleague:<名称>]`、开源项目 `[open-source:<名称>@<tag|commit>]`、一次性对象 `[external:<通用名>]`。
   - **对比记录落档**：登记对象 → [position/compare/](../../../position/compare/) `YYYY-MM-DD-vs-<对象>.md`（头部基线锚定 + 对比报告 + 借鉴清单 + **定位新认知**（对 position 基准的新认知，无则记「无」）+ **操作者最终决定**两节必填）；一次性对象 → 任务目录 `learn-report.md`。
   - **清单经操作者裁决后两轨分流**：需**立即优化** → 建对应 `#workspace-optimize` 任务（compare/learn-report 登记任务指针）；**有价值待观察** → 登记 `BACKLOG.md`（标来源 + 触发信号）。**不直接写 `exps/`/`notes/`/skill/WORKFLOW**——裁决后落真源时按性质分流（机制 → WORKFLOW/skill；经验 → `exps/` 标来源；知识 → `notes/`）并过下方门禁。
   - 对比**过程留痕不单独写 exps**——登记同事库的同步动作在 `position/colleague.md` 记摘要 + 指向 compare 记录。
   - 软链：一轮对比跑完建议接一次 workspace-grill（BACKLOG 唯一评估入口）。

## Gates（对比门禁）

**产出借鉴清单前，以下全「是」才交清单**；任一「否」→ 补对比：

- [ ] **同步前置**：是否同步了最新仓库、对比记录头部锚定基线（仓库 + tag/分支 + SHA + 日期；开源项目须为 stable release tag 而非分支 HEAD）？
- [ ] **基准对照**：是否读过 [position/README.md](../../../position/README.md) 并以其为锚？会偏移定位/初心的借鉴点是否单独标注交裁决？
- [ ] 对比报告维度是否与对象类型匹配（同事库 = 范式 + 内容**双维度**；开源项目 = **仅架构/范式维度**），而非只看其一或越界？
- [ ] 每条发现是否**来自真实读取的双方内容**、能指向具体出处，而非凭印象或预设结论？
- [ ] **已定型判据**：候选机制是否有演进证据（CHANGELOG 打磨记录 / 任务使用痕迹）？试行期/纸面设计是否标注且未建议直接落地（最多进 BACKLOG 观察位）？
- [ ] 借鉴清单是否**分类分优先级**（同事库两类 / 开源项目仅治理方法论类 × P0/P1/P2）？
- [ ] 每条借鉴点是否标注「借鉴点 → 己方缺口 → 适配注意」，而非照搬对方机制？
- [ ] **来源中立 + 中立化转换**：每条去掉对另一库的引用是否仍成立？公司名/产品名/人名一律剥离、业务措辞转通用、可变点标 `【模板占位】`？
- [ ] **合并优先（防重复）**：借鉴点是否先查己方既有内容（grep 相关 INDEX/真源）能否并入，而非直接新增平行机制？
- [ ] **宁可晚进**：候选默认先进 BACKLOG 等真实使用召唤；「直接落地」仅限操作者逐条裁决确认，不批量打包采纳？
- [ ] **认知护栏**：grep 零结果只能表述为「当前搜索范围内未观察到」，不得下「对方没有 X / 这是他们独有」的断言？
- [ ] **仅分析 + 裁决分流**：是否未自动改 exps/skill/WORKFLOW？对比记录（含定位新认知 + 操作者决定）是否落对位置（登记对象 `position/compare/` / 一次性对象任务目录）、清单是否按裁决两轨分流？

> 反例信号：借鉴清单被纠「漏了维度 / 照搬了不适配的机制 / 抄了对方文件路径 / 凭印象下结论 / 没同步就对比 / 把试行态当成熟经验」，几乎都是上面某条没过。

## Outputs

- **对比记录**：登记对象 → `position/compare/YYYY-MM-DD-vs-<对象>.md`；一次性对象 → `workspace-optimize/task-<日期>-learn-<对象>/learn-report.md`（含证据与逐条裁决结果，留任务目录）。
- **借鉴清单两轨分流（经操作者裁决）**：立即优化 → `#workspace-optimize` 任务；待观察 → `BACKLOG.md`（含「借鉴点→缺口→适配注意」+ 来源 + 触发信号）。
- **沉淀物（裁决后）按性质落真源**：机制 → WORKFLOW/对应 skill；经验 → `exps/`（来源标注）；知识 → `notes/`；候选 → BACKLOG。落真源时过来源中立 + 中立化 + 防重复门禁，改带 frontmatter 的文档同步 bump `updated-at`。
- **无独立状态机**：本 skill 由 `#workspace-optimize` 任务承载（两态 Lifecycle 见 workspace-ops），本文件 frontmatter 不设 `states:`。

## Verify（收尾自检）

- [ ] 借鉴清单条条有演进证据（或明确标注「无演进证据/试行期」，未混入建议落地）？
- [ ] 全程只读：未写外部路径、未读外部密钥载体、远端动作经授权、未 push？
- [ ] 对比记录锚定基线并落对位置（登记对象 `position/compare/`；一次性对象任务目录）？
- [ ] 每条沉淀过「来源中立 + 中立化 + 防重复」检查（去掉外部引用仍成立；无公司名/产品名/人名；无平行机制）？
- [ ] 裁决前未动任何真源（WORKFLOW / skills / exps / notes / BACKLOG 均无提前写入）；试行期机制已进 BACKLOG 观察位？
- [ ] 一轮对比跑完已提示软链 workspace-grill？
