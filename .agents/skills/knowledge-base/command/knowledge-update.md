# /knowledge-update

将本次任务的业务变更记录为增量笔记，写入 `notes/temp/` 目录。

## 参数

- `$ARGUMENTS`（可选）：简要描述本次变更。不传则由 Agent 根据当前对话上下文自动总结。

## 执行步骤

### 1. 确定变更范围

- 如果提供了 `$ARGUMENTS`，以其作为变更描述
- 如果未提供，回顾当前对话中完成的任务，总结变更内容

### 2. 评估是否需要记录

仅当变更涉及以下内容时才创建 temp 文件：
- 业务逻辑变化（新增/修改/删除功能）
- 数据模型变更
- API 接口变化
- 权限/可见性规则调整

以下情况**不需要**记录：
- 纯样式微调
- typo 修复
- 配置文件格式调整
- 依赖版本更新

### 3. 确定序号

1. 扫描 `notes/temp/` 目录下所有 `*.md` 文件
2. 从文件名中提取最大序号（格式 `{序号}-*.md`）
3. 新序号 = 最大序号 + 1（如果没有文件则从 `01` 开始）
4. 序号格式为两位数字（如 `01`、`02`、`12`）

### 4. 确定关联主文档

根据变更涉及的模块，查阅 AGENTS.md 中的知识库配置，确定应汇总到哪个主文档的哪个章节。

### 5. 创建 temp 文件

在 `notes/temp/` 下创建 `{序号}-{kebab-case 描述}.md`。

先读取 skill 的 `references/temp-template.md` 获取最新模板。模板包含以下字段：
- 变更类型（feature / bugfix / refactor / api-change / permission-change）
- 变更原因
- 涉及的模块/文件
- 业务流程变化
- 新增/删除的功能点
- 关联主文档（必填）

### 6. 输出结果

告知用户已创建的 temp 文件路径和序号。

## 示例

```
/knowledge-update                                    # 自动总结当前任务变更
/knowledge-update 用户管理模块新增批量导入功能     # 指定变更描述
```
