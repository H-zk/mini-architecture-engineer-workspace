# /knowledge-refactor

重构知识库的文档结构。当知识库因为长期维护变得冗余、混乱，或业务模块发生重大重组时，使用本命令重新规划文档拆分/合并方案并执行。

## 参数

- `$ARGUMENTS`（可选）：
  - 不传：交互式模式，先分析再提出方案，等用户确认后执行
  - `--plan-only`：只生成重构计划，不执行
  - `--from-plan {计划文件路径}`：按照已有计划执行重构

## 触发条件

本命令通常在以下情况下被触发：

- `/knowledge-check` 检测到知识库结构需要重构，并已生成重构计划
- 用户主动发现知识库结构不合理
- 项目经历重大业务重组（模块合并/拆分）

## 执行步骤

### 1. 分析当前知识库结构

1. 读取 `AGENTS.md` 中的知识库目录结构声明
2. 列出所有主文档，读取每个文档的：
   - 内容长度（行数）
   - 章节结构
   - 覆盖的业务域
   - 引用的源码文件
3. 识别结构问题：
   - **过大文档**（超过 300 行）：可能需要拆分
   - **过小文档**（少于 20 行）：可能需要合并
   - **职责重叠**：多个文档覆盖同一业务域
   - **职责模糊**：文档内容与其标题/定位不匹配
   - **引用冲突**：同一源码文件被多个主文档重复描述

### 2. 生成重构方案

如果未指定 `--from-plan`，根据分析结果生成重构方案：

#### 方案内容

对每个需要的操作，明确说明：

**拆分操作**：

```text
拆分：notes/05-user-management.md
  → notes/05-user-auth.md    （认证相关：登录/注册/权限）
  → notes/05b-user-profile.md （用户信息相关：资料/设置/偏好）
  原因：文档超过 350 行，认证和用户信息是两个独立业务域
```

**合并操作**：

```text
合并：notes/03-auth-permissions.md + notes/04-user-roles.md
  → notes/03-user-access.md
  原因：两者业务高度关联，且原始文档都较小
```

**重组操作**：

```text
重组：调整编号和文件名
  05-user-auth.md       → 05-user-auth.md（不变）
  05b-user-profile.md   → 06-user-profile.md（重编号）
  06-notification.md    → 07-notification.md（后移）
```

### 3. 确认方案

- 如果是 `--plan-only`：将方案写入 `temp/` 下，文件名格式 `knowledge-refactor-{日期}.md`，输出计划路径后结束
- 如果是交互模式：向用户展示方案，等待确认后继续
- 如果是 `--from-plan`：读取指定计划文件，确认后继续

### 4. 执行重构

对每个操作按顺序执行：

1. **创建新文档**：基于原文档内容，按新结构重新编写
   - 保持引用的文件路径和行号准确
   - 保持统一的文档格式模板
   - 写入新的元数据（`last-checked` 和 `last-updated` 设为当天）
2. **更新 AGENTS.md**：修改 `## 知识库 → ### 目录结构` 中的文件列表和 `### 业务域到文档映射` 表
3. **处理 temp 引用**：检查 `notes/temp/` 中是否有引用被重构文档的 temp 文件，更新其 `关联主文档` 字段
4. **删除旧文档**：确认新文档就绪后删除旧文件

#### 编号重分配规则

当拆分或合并文档导致编号冲突时，按以下规则处理：

1. **保留最小编号**：拆分时，原文档保留原编号，新文档使用下一个可用编号
   - 例：拆分 `05-user-management.md` → `05-user-auth.md`（保留）+ 新增 `XX-user-profile.md`
2. **级联后移**：新增文档的编号如果与现有文档冲突，冲突文档及之后所有文档编号 +1
   - 例：新增 `06-user-profile.md` 但已有 `06-notification.md` → 原 `06` 变 `07`，原 `07` 变 `08`，以此类推
3. **合并取小编号**：合并多个文档时，使用最小的编号，释放的编号由后续文档级联前移
4. **更新 AGENTS.md**：同步修改 `## 知识库 → ### 目录结构` 中的文件列表和 `### 业务域到文档映射` 表

### 5. 输出结果

```text
知识库重构完成：
  新增：05-user-auth.md, 06-user-profile.md
  删除：05-user-management.md
  更新：AGENTS.md（目录结构 + 业务域映射）
  temp 文件引用更新：2 个
```

## 示例

```bash
/knowledge-refactor                              # 交互式：分析 → 方案 → 确认 → 执行
/knowledge-refactor --plan-only                  # 只生成重构计划文件
/knowledge-refactor --from-plan temp/knowledge-refactor-2026-05-22.md  # 按计划执行
```
