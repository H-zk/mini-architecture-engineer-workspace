# /knowledge-merge-temp

读取 `notes/temp/` 下所有增量笔记，按"关联主文档"字段分组，合并到对应的主文档中。

## 参数

- `$ARGUMENTS`（可选）：
  - 不传：合并所有 temp 文件
  - 指定序号（如 `03`）：只合并指定序号的 temp 文件
  - 指定 `--dry-run`：预览合并计划但不实际执行

## 触发条件

本命令在以下情况下应被主动建议或执行：

- `notes/temp/` 下的文件数 ≥ 5
- 用户主动要求汇总
- 用户通过 `/knowledge-merge-temp` 命令触发

## 执行步骤

### 1. 扫描 temp 文件

1. 列出 `notes/temp/` 下所有 `*.md` 文件
2. 如果指定了序号，只处理对应文件
3. 如果没有 temp 文件，告知用户并结束

### 2. 读取并解析

对每个 temp 文件：

1. 读取文件内容
2. 提取 `## 变更类型` 字段，记录变更类型标签
3. 提取 `## 关联主文档` 字段，确定目标主文档路径和章节
4. 提取变更内容（变更原因、涉及文件、流程变化、功能点）

### 3. 按主文档分组

将 temp 文件按目标主文档分组。如果有 temp 文件指向不存在的主文档：

- 报告错误
- 跳过该 temp 文件（不删除）

### 4. 合并到主文档

对每个主文档，逐一整合对应的 temp 内容：

1. **读取主文档**当前内容
2. **判断合并策略**：
   - 如果 temp 内容是已有章节的更新 → 更新对应章节的内容
   - 如果 temp 内容是新增知识点 → 追加到主文档的合适章节末尾
   - 如果 temp 内容是新增业务流程 → 在 `## 业务流程` 下新增子章节
3. **保持格式一致**：合并后的主文档仍遵循统一格式（标题 → 概述 → 关键文件 → 业务流程 → 数据模型 → 注意事项）
4. **去重**：避免主文档中已有的信息被重复写入

#### 合并规则

按章节分别处理：

- **概述**：不修改（概述应由 `/knowledge-improve` 统一重写）
- **关键文件**表格：追加 temp 中新出现的文件、移除已删除的文件
- **业务流程**章节：新增流程追加子章节、已有流程的修改替换描述
- **数据模型**章节：新增字段追加、删除字段标记或移除
- **注意事项**章节：去重后追加新的注意事项
- **变更历史**章节：仅在产生结构性变更（新增/删除章节、业务域变化）时追加记录，格式 `| {日期} | 合并 temp/{序号}-{描述}.md |`。追加后如果超过 5 条，裁剪最旧的记录。内容微调不记录。

合并完成后更新文档末尾元数据中的 `last-updated` 为当天日期。

如果是 `--dry-run` 模式，只输出合并计划，不写入文件。

### 5. 写入主文档

将合并后的内容写回各主文档。

### 6. 清理 temp 文件

- 只删除成功合并的 temp 文件
- 合并失败的 temp 文件保留，并报告原因

### 7. 输出结果

报告：

- 已合并的 temp 文件列表
- 更新的主文档列表
- 失败/跳过的文件及原因（如有）
- `notes/temp/` 下剩余文件数

## 示例

```bash
/knowledge-merge-temp              # 合并所有 temp 文件
/knowledge-merge-temp 03           # 只合并 03-xxx.md
/knowledge-merge-temp --dry-run    # 预览合并计划
```
