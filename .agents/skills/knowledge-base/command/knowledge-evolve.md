# /knowledge-evolve

分析知识库管理 skill 自身的有效性，基于知识库的实际使用情况发现问题模式，提出对 skill（模板、命令、规范）的改进建议并执行。

本命令的核心目标：**让 skill 根据知识库的实际维护经验持续迭代自身**，而非固守初始设计。

## 参数

- `$ARGUMENTS`（可选）：
  - 不传：完整审视，输出改进建议
  - `--apply`：审视后自动执行确认的改进
  - `--plan-only`：只输出改进计划，不执行

## 触发条件

本命令在以下情况下应被建议或执行：

- `/knowledge-check` 检测到反复出现的同类问题（如多次引用失效、多个文档同时过时）
- 知识库维护过程中，现有命令或流程无法有效覆盖新场景
- 用户发现 skill 的模板、命令或规范存在不足
- 累计执行 10 次以上 `/knowledge-update` 后，建议执行一次

## 审视维度

### 1. 使用模式分析

分析 `notes/temp/` 和主文档的变更历史，识别模式：

1. **temp 积压频率**：如果 temp 文件经常超过 5 个才合并，说明 `/knowledge-merge-temp` 的触发门槛或流程可能需要调整
2. **同一文档反复过时**：如果某个文档在 `/knowledge-check` 中反复被标记为需要更新，说明该文档的粒度或覆盖范围可能不合理
3. **temp 文件关联混乱**：如果多个 temp 文件的"关联主文档"指向不明确的章节，说明文档划分或 temp 模板可能需要调整
4. **命令使用不均**：如果某些命令从未被使用（如 `/knowledge-refactor`），评估是否需要简化或合并

### 2. 模板有效性分析

检查现有模板是否匹配实际需求：

1. **主文档模板**：检查主文档中是否有反复出现的章节未被模板覆盖
2. **temp 模板**：检查 temp 文件中是否有字段经常为空或不适用
3. **编写规范**：检查是否有规范被频繁违反（说明规范不合理或不够清晰）

### 3. 流程覆盖度分析

检查 skill 的命令和工作流是否能覆盖所有常见场景：

1. **缺失场景**：知识库维护中遇到但现有命令无法处理的情况
2. **冗余步骤**：命令中可以简化的流程
3. **边界情况**：命令在极端情况（空目录、大量文件、跨模块变更）下的表现

### 4. 交叉引用健康度

分析知识库中交叉引用的实际效果：

1. **重复内容**：多个文档仍然描述同一知识点（交叉引用原则未生效）
2. **悬空引用**：引用的章节在目标文档中不存在或已重命名
3. **引用方向不合理**：频繁引用的文档可能是候选拆分对象

## 执行步骤

### 1. 收集数据

1. 读取所有主文档的内容和元数据
2. 扫描 `notes/temp/` 目录（如果有的话）
3. 读取 skill 的当前配置：`references/` 下的模板和规范、`scripts/` 下的脚本

### 2. 分析问题模式

按上述 4 个维度逐一分析，记录发现的问题和模式。

### 3. 生成改进建议

对每个发现的问题，提出具体的改进方案：

```text
skill 改进建议：

📐 模板改进：
  1. doc-template.md 应增加「错误处理」章节模板
     原因：05-user-management、07-notification 文档中自发添加了错误处理章节

📝 规范改进：
  2. writing-guidelines.md 应明确「关键文件」表格的排序规则
     原因：多个文档的文件表格排序不一致

🔧 命令改进：
  3. /knowledge-update 应支持批量变更（一次任务涉及多模块）
     原因：3 次 temp 文件出现了"关联主文档"指向 2+ 个文档的情况
```

### 4. 确认与执行

- 如果指定了 `--plan-only`：将建议写入 `temp/knowledge-evolve-{日期}.md`，输出路径后结束
- 如果指定了 `--apply`：向用户展示建议，等待确认后逐项执行
- 默认模式：向用户展示建议，逐项询问是否执行

### 5. 执行改进

对每项确认的改进：

1. **模板修改**：更新 `references/` 下的模板文件
2. **规范修改**：更新 `references/writing-guidelines.md`
3. **命令修改**：更新 `command/` 下的命令定义文件（本 skill 的 command 目录）
4. **脚本修改**：更新 `scripts/` 下的校验脚本

每次执行后记录变更摘要。

### 6. 输出结果

```text
skill 自我迭代完成：
  已执行：3 项改进
  跳过：1 项（需进一步讨论）

  改进明细：
    ✅ doc-template.md：增加「错误处理」章节模板
    ✅ writing-guidelines.md：明确关键文件排序规则
    ✅ knowledge-update.md：支持多模块变更
    ⏭️ 知识库目录结构自动生成：待讨论

  建议后续操作：
    /knowledge-check  # 验证改进后的效果
```

## 可执行的改进类型

| 改进对象 | 操作 | 风险等级 |
|---------|------|---------|
| `references/*.md` 模板 | 修改章节结构、增加/删除字段 | 低 |
| `references/writing-guidelines.md` | 增加规范条目、澄清规则 | 低 |
| `command/*.md` 命令定义 | 修改步骤、增加参数、调整流程 | 中 |
| `scripts/*.js` 校验脚本 | 增加检查项、修复误报 | 中 |
| `SKILL.md` 核心定义 | 修改工作流、增加命令 | 高 |

高风险的改进需要用户明确确认才能执行。

## 注意事项

- 本命令修改的是 **skill 自身**（模板、命令、规范），不直接修改 `notes/` 下的知识库文档
- 如果改进涉及新增命令，需要同时在 `SKILL.md` 和 `command/` 下同步更新
- 改进后建议执行 `/knowledge-check` 验证效果
- 本命令不应频繁执行，通常每 1-2 个月或在发现明确问题模式时执行一次

## 示例

```bash
/knowledge-evolve                    # 审视 skill，输出改进建议
/knowledge-evolve --apply            # 审视并自动执行确认的改进
/knowledge-evolve --plan-only        # 只输出改进计划
```
