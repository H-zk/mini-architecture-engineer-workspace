# /knowledge-improve

对比知识库主文档与当前代码，找出过时或不准确的内容，更新主文档使其与代码保持同步。

## 参数

- `$ARGUMENTS`（可选）：
  - 不传：更新所有主文档
  - 指定编号或文件名（如 `05` 或 `05-user-management.md`）：只更新指定文档

## 执行步骤

### 1. 确定更新范围

1. 从 `AGENTS.md` 的 `## 知识库 → ### 目录结构` 解析主文档列表
2. 如果 `$ARGUMENTS` 指定了编号或文件名，只处理该文档
3. 如果未指定，处理所有主文档

### 2. 逐文档对比与更新

对每个主文档：

#### 2a. 读取文档内容

提取文档中引用的所有文件路径和行号。

#### 2b. 验证引用的文件

1. 检查文档中引用的文件路径是否仍然存在
2. 对于引用了行号的位置，检查该行号处的代码是否仍匹配文档描述
3. 记录所有已失效的引用

#### 2c. 分析代码变化

1. 对文档覆盖的业务域，扫描相关源码目录
2. 识别文档中**未覆盖的新功能**：
   - 新增的路由/视图/页面
   - 新增的状态管理字段和方法
   - 新增的模块/组件
   - 新增的 API 接口
 3. 识别文档中**已不存在的旧功能**：
   - 已删除的路由/视图/页面
   - 已移除的状态管理字段
   - 已删除的模块或工具函数

#### 2d. 更新文档

根据分析结果更新主文档：

1. **修复失效引用**：更新或移除指向已删除文件的内容
2. **补充新内容**：将新发现的功能按文档格式添加到对应章节
3. **移除过时内容**：删除描述已不存在功能的段落
4. **更新数据模型**：补充新增字段，移除已删除字段
5. **更新业务流程**：反映代码中的流程变化
6. **更新变更历史**：仅当本次更新产生了结构性变更（新增/删除章节、数据模型重大变化）时，在 `## 变更历史` 表格中追加记录。内容微调、行号修复等不记录。追加后超过 5 条时裁剪最旧记录。

如果文档中缺少 `## 变更历史` 章节，在 `## 注意事项` 之后补充该章节。

#### 2e. 更新元数据

更新文档末尾的元数据块：

```markdown
<!--
last-checked: {当天日期}
last-updated: {当天日期}
-->
```

### 3. 输出报告

输出每个文档的更新摘要：

```
notes/05-user-management.md:
  ✅ 新增：批量导出流程（services/batch_export.py）
  ✅ 更新：API 层新增 3 个接口
  ✅ 修复：行号引用 42 → 58（代码偏移）
  ❌ 移除：已废弃的 legacy-import 流程描述
```

## 注意事项

- 更新时保持文档的原有结构和格式风格
- 只更新确实有变化的内容，不做无意义的重写
- 如果代码变化过大导致文档需要重构而非更新，建议使用 `/knowledge-refactor`
- 更新完成后不需要写入 temp，直接修改主文档

## 示例

```
/knowledge-improve              # 更新所有主文档
/knowledge-improve 05           # 只更新 05-user-management.md
/knowledge-improve 02-api-reference.md  # 指定完整文件名
```
