# customer-report.md 七章结构与写作原则

> 本文件是 `case-troubleshoot` 可选产物 customer-report.md 的参考资料：产出前必读。与内部文档写法**完全不同**——读者是客户（非开发人员）。

## 七章标准结构（以严重度为骨架，可增减）

1. 现象复述（客户视角：看到什么、做了什么、哪里不对）；
2. 事件时间线（客户最关心：何时出问题、何时反馈、**何时恢复**——用客户时区，附「反馈到恢复耗时」）；
3. 问题出在哪个环节（一句话定位，明确不是客户操作错）；
4. 原因（通俗分层：诱因 + 关键问题，用类比）；
5. 已采取的处理（做了什么恢复 + 影响范围说明）；
6. 后续防范（诚实标注「评估中/排期中」，**不说已永久修复**）；
7. 技术附录（供客户方技术人员，可选；与前六章**隔离**）。

## 写作原则

- **零代码零术语**（前六章——表名/服务名/错误码全转通俗描述，技术细节只进附录）。
- **不归责客户**（中性措辞，如「此前同一批数据被反复触发」）。
- **诚实区分临时/根治**：临时处理说「已恢复」、长期修复评估中标「评估中」——对应 conclusion「修复建议」双轨，临时方案是对客沟通素材。
- 时间线用客户时区；「哪个环节」要明确。

## 信息来源

- 现象 + 时间线 = 工单系统的评论 / 动态记录（按你的接入方式获取，见 GUIDE §1.2；时间戳换算客户时区）＋ 工单排查结论。
- 根因 + 技术细节 = `notes/` + `solution.md`。
- 处理动作 = 工单评论里的处置记录（谁、何时、做了什么）。
