# case-troubleshoot

> 本文是 CASE 排查标准流程的单一真源。

## When（何时触发）

- 消息开头标签 `#case` / `#排查`，且需要写交付物/留档。
- 即时能答的简单问题不打 `#case`。

## Inputs

- 现场证据：失败接口、响应码、错误信息、发生时间（带时区）、请求参数或 HAR（脱敏）、requestId 等关联键。
- 代码链：入口 → 拦截器 → Controller → Service → DAO → 配置。
- 工单历史评论、他人结论：**只作待验证假设**，不作事实继承。

## Steps

1. **记录现状** → `README.md` 写清现象、版本、环境、复现路径、影响范围、客户/工单信息（静态背景）。【模板占位：工单信息按你的工单系统填写，深度接入方式见 GUIDE §1.2】
2. **先锁失败接口**：有明确页面/现场错误时，优先取得失败接口 + 响应码 + 时间 + requestId。没有失败接口前不投入结论性描述。
3. **建立证据链**：数据流（数据库当前状态、字段、时间线）+ 日志链（requestId/taskId/fileId 贯穿）+ 代码链；形成假设 → `analysis.md` 列候选原因与验证方式，逐条验证，推翻/确认都记录。
4. **分区记录**（`analysis.md` / `conclusion.md`，见 Outputs）：
   - 已确认事实（同一请求/业务对象的运行时证据，或等价环境稳定复现 + 单变量修正使问题消失）
   - 高可信假设（仅有代码路径/配置缺口/现象吻合，无论置信度多高）
   - 待验证项
   - 修复建议
   - 修复验证结果
   - 非技术结论（售后口径，必填；「待验证项」非空时写当前进展口径）
5. **定位根因、给出方案** → 收敛到根因，而非止步于表象；价值链优先序 = 找出原因 → 给出临时方案（快速止血、处理客情、减少客诉）→ 给出完整方案；`conclusion.md` 给修复与预防（临时 + 完整双轨，见 Outputs「修复建议」分区要求）。
6. **完成前门禁**：见 Gates；收尾评估是否沉淀经验/补测试/改 `notes/`。

## Gates（证据门禁）

- **「已确认根因」门槛**：必须满足任一：
  - 取得同一失败请求/业务对象的运行时证据，直接显示目标机制触发。
  - 在与线上部署 commit、关键配置、输入等价的环境稳定复现，并通过单变量修正使问题消失。
- 仅有代码路径、配置缺口、现象吻合 → 只能进「高可信假设」，**不得**传播为「已确认根因」。
- 代码路径推导 ≠ 线上实际请求已走该分支；日志现象 ≠ 代码机制已确认。
- 证据必须落到同一个业务对象或同一次请求。
- 否定结论必须贴查询条件和限定范围（过程中的探索性排除可简化，不必每条贴查询）。
- 存在决定性待验证项时，不得把「高可信假设」标为「已确认根因」。
- 取证只在工作区内进行；如需访问客户环境/外部系统，先获操作者授权。

## Lifecycle（状态机 + reopen 协议）

- **状态集**：`{进行中, 已完成}` 两态（frontmatter `states:` 即 `workspace-check.py` 的机器校验登记处）。等待语义（等客户回复 / 工单流转 / 日志窗口 / 外部确认，case 最高频）用 `blocker` 字段承载（`进行中` + blocker 非无 = 等外部，next 写解阻后动作；无「阻塞」态，机制见 [WORKFLOW §2.6](../../../WORKFLOW.md) 状态机不变量）。
- **路径**：`进行中 → 已完成`（收尾）+ **reopen 回边 `已完成 → 进行中`**：
  - **判据（一句话）**：要修正 / 闭环 `conclusion`（新证据推翻或补全既有结论）→ reopen（原任务复活）；只等修复上线对账 → **不 reopen**，用「待对账」钩子（WORKFLOW §2.6）由回顾流程建新任务。
  - **协议** = [WORKFLOW §2.6](../../../WORKFLOW.md) 通用 reopen 协议（活跃区硬截止 / 翻回留痕收场 / 新会话增补 / `sprint-version` 不变）；case 特有：增补物 = 修正 / 闭环 `conclusion`（与上方判据对应）。
- task status 表示**工作区任务交付状态**，不表示线上问题生命周期。
- 调查交付已完成、操作者接受结论时可标 `已完成`（完成判定权见 WORKFLOW §2.6 完成前闸门）；修复状态在 `conclusion.md` 另行记录。
- 只有任务验收口径明确包含「上线修复验证」时，未验证才阻止任务完成。
- 修复由其他团队实施或另行排期时，创建关联修复任务，不让调查任务永久阻塞。
- **完成证据门禁**：约束**证据分级诚实**而非任务状态——「已确认根因」处必过 Gates 门槛（不冒充）、待验证项非空时 conclusion 必含下一步验证计划、INDEX 摘要证据状态不超 conclusion；满足即可完成（「高可信假设 + 待验证计划」收口是合法完成形态）。
- **review 事件**：case 无独立 review 环节（跨标签机制见 [WORKFLOW §2.6](../../../WORKFLOW.md) 状态机通用协议）；操作者完成确认留痕记 CURRENT 历史正文一句。

## Outputs（目录产物）

任务目录（`case/case-YYYY-MM-DD-描述/`）必需产物：

- `README.md`：现象、环境、复现条件、影响范围、客户/工单信息与索引。
- `CURRENT.md`：状态（CURRENT schema，`status` ∈ 本 skill `states:`）。
- `analysis.md`：调查过程、证据链。
- `conclusion.md`：固定分区（顺序如下，「非技术结论」必填——「待验证项」非空时该分区写当前进展口径而非最终定论）：

  ```text
  ## 已确认事实
  ## 高可信假设
  ## 待验证项
  ## 修复建议
  ## 修复验证结果
  ## 非技术结论（售后口径）
  ```

  「修复建议」分区双轨要求：**根因明确时**（根因已定位——已确认，或高可信定位到具体原因）必含**临时方案**（面向客情的即时止血措施，减少客诉）+ **完整方案**（根治修复）；**无合理临时方案时必须显式说明**——写明「无合理临时方案」及原因，不得静默缺位（这本身是对客沟通的重要信息）。
- `evidence/`：脱敏证据（客户密码/Token/Cookie 不得落盘；大体量证据进受控外部存储，任务内只留检索信息与校验哈希）。

### customer-report.md（对客回复，可选产物）

CASE 排查完需要给客户（非开发人员）一个交代时产出，与内部文档写法**完全不同**——七章标准结构与写作原则见 [references/customer-report.md](./references/customer-report.md)（产出前必读）。

- **询问点** = 完成确认对话中与沉淀询问并列（「是否已完成？→ 要沉淀经验吗？要输出对客回复吗？」）。
- **产出时序**：操作者确认需要 → 草稿 → 操作者审核 → frontmatter 标 `status: 可对外` → 才改任务 `status: 已完成`（完成前置产物，避免完成后 reopen 补）；不需要 → 直接收尾。
- **同 CASE 三产出关系（互不替代）**：`notes/<域>/<功能>.md`（业务知识沉淀，给未来排查）＋ `<task>/solution.md`（工程建议，给研发评估）＋ `<task>/customer-report.md`（对外交代，给客户/售后转发）。
- 不进 workspace-check 产物机器表（可选产物，本节门禁人工判）。

## Verify（DoD）

- **根因输出必选、证据等级可选**：conclusion 必含明确根因表述 + 失败链路摘要（请求链 / 数据流 / 代码链）；根因可标「已确认」（必过 Gates 门槛）或「高可信假设 + 待验证计划」——两者都是合法完成形态，**不谎称已确认**。
- 结论证据等级明确、与 Lifecycle 完成证据门禁自洽；`conclusion.md` 六分区齐全（含必填「非技术结论（售后口径）」）；「待验证项」非空时 conclusion 必含下一步验证计划；根因明确时「修复建议」含临时方案 + 完整方案双轨，无合理临时方案时显式写明及原因（见 Outputs）。
- 否定性结论已带限定条件、查询条件已贴出；佐证与结论是**同一对象**（非同类）。
- 修复方案已验证有效（或有明确验证计划）；预防措施已提出。
- 敏感信息已脱敏；可复用经验已按 WORKFLOW §2.4 沉淀（如有）。
- `CURRENT.md` 符合 schema（`status` ∈ 本 skill `states:`；操作者完成确认留痕在 CURRENT 历史正文，不写 `review:` 事件）。
- 若产出对客回复：customer-report.md 已过操作者审核并标 `status: 可对外`（见 Outputs 时序）。
- 跑 `python .tools/workspace-check.py --task <当前任务>`，本 CASE 任务无 error。
- INDEX 摘要不比 conclusion 正文证据状态更确定。
