# 代码探索清单

按优先级排列。P0 为必查项，P1 为建议查项，P2 为可选查项。

探索清单中的具体搜索关键词和文件路径会因项目技术栈而异，Agent 需要根据项目实际使用的语言和框架灵活调整搜索策略。

## P0 必查项 — 遗漏后 Agent 一定会写错

### 1. 用户通知/反馈方式

**探索目标**：找出项目统一的用户提示、通知、错误展示方式，避免 Agent 使用底层库的原生方法或随意选择方案。

**跳过条件**：项目无 UI 层（纯后端服务、CLI 工具、库项目）。判断方式：无前端入口文件（index.html、App.vue、main.ts 等）。

**探索策略**：

- 搜索项目中封装的通知/消息/日志工具函数
- 检查是否有对 UI 库原生方法的二次封装或替代
- 搜索常见通知方法名：`notify`、`message`、`toast`、`alert`、`flash`、`toastify`
- 检查是否有明确禁止直接使用某些底层方法的约定

**关注点**：

- 项目是否封装了自定义的通知方法？
- 不同场景（成功/失败/警告/错误）是否有对应的方法？
- 是否有错误码到用户可见消息的映射机制？

### 2. API 数据转换约定

**探索目标**：找出 API 返回数据到业务层使用的转换约定，避免 Agent 直接使用原始格式。

**跳过条件**：项目无外部 API 调用（纯前端静态页、无网络请求的库）。判断方式：无 HTTP 客户端（axios、fetch 封装、requests 等）。

**探索策略**：

- 搜索布尔值的转换函数（如 API 返回 `'Y'/'N'`、`'true'/'false'`、`1/0` 等非标准布尔值）
- 搜索枚举值的映射（如状态码到枚举/常量的转换）
- 搜索时间/日期格式转换
- 检查工具函数文件中的数据转换辅助函数

**关注点**：

- API 层和业务层之间是否有统一的数据转换层？
- 是否有专门处理特定格式的工具函数（如 Y/N 转布尔、状态码映射）？
- Agent 直接使用原始 API 数据会导致什么问题？

### 3. 跨模块通信方式

**探索目标**：找出模块间通信的统一方式，避免 Agent 选择错误的通信机制。

**跳过条件**：单体小型项目，模块间无跨层通信需求。判断方式：src 下只有单一层级目录，无 services/stores/events 等分层目录。

**探索策略**：

- 搜索事件总线、消息队列、观察者模式的实现
- 搜索依赖注入、服务定位器的使用
- 搜索发布/订阅模式（`emit`、`dispatch`、`publish`、`subscribe`、`on`、`notify`）
- 区分框架提供的通信方式（如组件 props/events）和项目自定义的通信方式

**关注点**：

- 不同层级的组件/模块之间分别用什么方式通信？
- 工具函数/服务层与业务逻辑层之间如何通信？
- 是否有全局事件系统？如果有，key 命名规范是什么？

### 4. 状态管理规则

**探索目标**：确定全局状态管理的命名空间、访问方式和模块划分规则。

**跳过条件**：项目无全局状态管理（纯后端无状态服务、无状态管理库的前端项目）。判断方式：无 store/vuex/pinia/redux/zustand 等状态管理相关文件。

**探索策略**：

- 找到状态管理的入口文件（store/仓库/上下文等）
- 检查模块是否有命名空间隔离
- 检查跨模块访问的方式（是否允许直接 commit 其他模块、是否需要 rootState/rootGetters）
- 搜索状态读写的方式（dispatch/commit、getter/setter、selector/dispatch 等）

**关注点**：

- 哪些模块有命名空间隔离，哪些没有？
- 跨模块状态访问的正确方式是什么？
- 是否有状态变更的副作用处理约定？

### 5. 自动注册/发现机制

**探索目标**：确定项目中是否有自动注册的模块（组件、服务、路由、插件等），避免 Agent 手动注册已自动注册的内容。

**跳过条件**：项目无自动注册机制（手动逐一导入的小型项目）。判断方式：搜索 `require.context`、`glob`、`import.meta.glob`、`auto_import` 无结果。

**探索策略**：

- 搜索 `require.context`、`glob`、`import.meta.glob`、`__import__`、`auto_import` 等批量加载机制
- 搜索基于目录扫描的自动注册逻辑
- 搜索基于命名约定的自动发现（如 Spring 的组件扫描、Python 的 `__init__.py` 导出）
- 检查入口文件中是否有批量注册的逻辑

**关注点**：

- 哪些类型的模块是自动注册的？
- 自动注册的命名约定或目录约定是什么？
- Agent 在哪些情况下不需要手动 import/register？

### 6. 国际化（i18n）工作流

**探索目标**：确定国际化的文件结构、key 命名规范、调用方式和新增文案流程。

**跳过条件**：项目无国际化需求（纯内部服务、无 i18n 库）。判断方式：无 i18n/locale/lang 相关目录或依赖。

**探索策略**：

- 找到语言文件/资源文件的存放目录
- 读取文件结构（扁平 vs 嵌套、单文件 vs 多文件、JSON vs YAML vs 其他格式）
- 搜索翻译函数的调用模式（组件/视图内 vs 工具/服务内）
- 检查参数化文案的占位符格式
- 确认新旧文件的关系和扩展方式

**关注点**：

- key 命名规范是什么（嵌套路径、点号前缀、扁平键名）？
- 组件内和工具函数内分别用什么方式调用翻译？
- 参数化文案的占位符格式和传参方式？
- 新增文案时需要修改哪些文件（是否需要同步多个语言文件）？
- 是否有应扩展的现有模块 vs 不应创建的新文件？

### 7. 环境与配置判断方式

**探索目标**：确定项目如何区分运行环境（开发/测试/预发布/生产）以及如何读取配置。

**跳过条件**：项目无多环境区分（单环境部署的工具/库）。判断方式：无 .env 文件、无环境变量引用、无 config/profile 目录。

**探索策略**：

- 检查构建工具配置中的环境变量注入（DefinePlugin、环境变量文件等）
- 搜索环境判断相关的常量或函数（`IS_TEST`、`IS_PROD`、`env()`、`config` 等）
- 检查不同环境下行为差异的代码分支
- 搜索 `.env`、`config/`、`settings.py` 等配置文件

**关注点**：

- 环境判断用的是构建时注入的全局常量，还是运行时的环境变量，还是配置文件？
- 不同环境下有哪些行为差异（如 SDK 版本、API 域名、日志级别）？
- Agent 在新增环境相关逻辑时应遵循什么模式？

### 8. 日志与错误处理约定

**探索目标**：确定项目统一的日志输出和错误处理方式。

**跳过条件**：项目使用标准库默认日志且无自定义封装。判断方式：搜索 `logger`、`logging`、`winston`、`pino` 等无自定义封装。

**探索策略**：

- 搜索日志工具（`logger`、`log`、`logging`）的使用方式
- 检查是否有远程日志上报机制
- 搜索错误处理的统一入口（拦截器、中间件、异常处理器）
- 检查错误码映射和用户可见错误消息的生成方式

**关注点**：

- 日志是否有分级（debug/info/warn/error）？不同级别的使用场景？
- 是否有日志上报到远程？Agent 新增日志时是否需要设置上下文信息？
- 错误是否有统一的处理链？Agent 在哪里应该抛出、哪里应该捕获？

### 9. 数据库访问约定

**探索目标**：确定项目数据库访问的统一方式，包括 ORM 用法、事务管理、连接池配置。

**跳过条件**：项目不使用数据库（纯前端、CLI 工具、无持久化服务）。判断方式：无 ORM/model/migration/database 相关目录或依赖。

**探索策略**：

- 找到 ORM 或数据库访问层的封装（SQLAlchemy、Prisma、TypeORM、GORM、MyBatis 等）
- 检查事务管理的模式（手动 vs 装饰器 vs 上下文管理器）
- 搜索连接池配置和获取连接的方式
- 检查查询构建的约定（链式 vs 原生 SQL、查询构造器模式）

**关注点**：

- 新增表/模型时遵循什么命名和结构约定？
- 事务应该在哪个层级开启？是否有统一的事务管理器？
- 连接是否自动管理（获取/释放），还是需要手动处理？

### 10. 配置管理

**探索目标**：确定项目的配置加载机制、环境变量处理和敏感信息管理方式。

**跳过条件**：项目配置极简（仅依赖单一 .env 文件且无敏感信息管理）。判断方式：配置文件少于 2 个且无加密/密钥管理相关代码。

**探索策略**：

- 搜索配置文件加载逻辑（`config`、`settings`、`dotenv`、`viper`、`pydantic-settings`）
- 检查环境变量的命名规范和分组方式
- 搜索敏感信息的处理方式（加密存储、密钥管理服务、.gitignore 规则）
- 检查配置的热更新机制（如适用）

**关注点**：

- 新增配置项时应遵循什么格式和位置？
- 敏感信息（数据库密码、API 密钥）如何获取和管理？
- 配置是否有类型校验和默认值机制？

## P1 建议查项 — 遗漏后特定场景会踩坑

### 11. 网络请求约定

**探索目标**：确定项目中 HTTP 客户端的使用方式，包括实例管理、拦截器、错误处理。

**升级为 P0 的条件**：项目有多个 HTTP 客户端实例或自定义拦截器链。

**探索策略**：

- 找到 HTTP 客户端的封装（axios、fetch 封装、requests、httpx 等）
- 确认有几个请求实例，各自的目标服务
- 检查拦截器/中间件的链式处理逻辑
- 确认成功判断条件（`code === 0` vs `code === 200` 等）

### 12. 功能开关/特性标志来源

**探索目标**：确定功能开关的获取和使用方式，避免 Agent 硬编码功能判断。

**升级为 P0 的条件**：项目大量使用功能开关控制核心业务流程。

**探索策略**：

- 搜索功能开关相关的变量名（`featureFlag`、`functionSwitch`、`enabled`、`toggle`）
- 确定功能开关有几个数据源（全局配置、用户角色、模块级别等）
- 检查开关值的类型和转换方式

### 13. 外部依赖/SDK 加载模式

**探索目标**：确定第三方 SDK 或外部依赖的加载和初始化模式。

**升级为 P0 的条件**：SDK 初始化顺序影响功能正确性（如需要先初始化再使用）。

**探索策略**：

- 找到 SDK 加载/初始化的统一入口
- 检查版本管理方式（是否需要同时更新多个环境的版本号）
- 确认 SDK 实例的创建和复用规则

### 14. 测试约定

**探索目标**：确定项目的测试方式、命名约定和运行命令。

**升级为 P0 的条件**：项目有强制测试覆盖率要求或 pre-commit 测试门禁。

**探索策略**：

- 检查测试目录结构（`tests/`、`__tests__/`、`test/`、`spec/`）
- 确认测试框架和运行命令
- 观察测试文件的命名约定和组织方式
- 检查是否有 mock/stub 的统一方式

### 15. 认证与授权模式

**探索目标**：确定认证令牌的获取、传递和刷新方式，以及权限检查的实现模式。

**升级为 P0 的条件**：项目涉及多角色权限控制或自定义认证协议。

**探索策略**：

- 搜索认证相关的代码（token、session、JWT、OAuth 等）
- 检查请求中认证信息的自动注入方式
- 搜索权限检查的实现（守卫、中间件、装饰器、权限函数等）

### 16. 中间件/拦截器链

**探索目标**：确定请求处理管道的组成和顺序，以及错误捕获层的组织方式。

**升级为 P0 的条件**：项目有复杂的多层中间件链（如鉴权→限流→日志→业务）。

**探索策略**：

- 找到中间件注册入口和顺序定义
- 搜索拦截器/过滤器的实现（`@UseGuards`、`@Middleware`、`before_action`、中间件函数等）
- 检查全局错误处理的捕获层级
- 确认中间件的作用范围（全局 vs 路由级 vs 控制器级）

**关注点**：

- 新增中间件应放在管道的哪个位置？
- 错误捕获在哪一层处理，哪些错误应向上抛出？

### 17. API 设计约定

**探索目标**：确定项目的 API 风格、路由定义规范、错误码体系和分页规范。

**升级为 P0 的条件**：项目是 API 为主的后端服务（非纯 UI 应用）。

**探索策略**：

- 搜索路由定义文件和注册方式
- 检查 API 风格（RESTful、RPC、GraphQL）和命名规范
- 搜索错误码/状态码的定义和映射
- 检查分页、排序、过滤的统一参数格式

**关注点**：

- 新增 API 应遵循什么命名和路径规范？
- 错误响应的统一格式是什么？
- 分页参数和响应格式是否有标准模板？

### 18. 并发与异步模式

**探索目标**：确定项目中并发处理和异步编程的统一模式。

**升级为 P0 的条件**：项目有高并发场景或复杂的异步流程（如工作流编排）。

**探索策略**：

- 搜索线程池/协程/异步任务的配置和使用方式
- 检查消息队列的生产者和消费者模式
- 搜索锁机制（分布式锁、乐观锁、悲观锁）的使用
- 检查异步任务的错误处理和重试机制

**关注点**：

- 新增异步任务应使用什么模式？
- 并发控制有哪些约束（如连接池大小、队列容量）？

## P2 可选查项 — 有助于理解但可通过读代码学到

### 19. 工具函数库

- 核心工具文件的位置和主要导出
- 常用工具函数的用途（加密/签名、重试、防抖节流、深拷贝等）
- 存储层的封装方式

### 20. 数据模型/Schema

- 数据模型的定义方式（ORM model、TypeScript interface、protobuf、JSON Schema 等）
- 模型验证方式
- 数据库迁移方式（如适用）

### 21. 路由/导航守卫

- 路由守卫/中间件的完整逻辑
- 权限检查的实现方式
- 未授权时的跳转/拦截逻辑

### 22. 构建与部署配置

- 构建工具的关键配置（仅限影响开发行为的部分，如路径别名、代理配置）
- 环境差异导致的行为变化
- 仅在 Agent 需要理解开发环境与生产环境行为差异时记录
