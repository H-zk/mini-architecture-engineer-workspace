# AGENTS.md 完善技能

通过深度分析项目代码实现，提炼对 Agent 开发真正必要的约定和模式，生成精炼、可操作的 AGENTS.md。适用于任何语言和框架的前端、后端、全栈项目。

核心原则：**AGENTS.md 只保留 Agent 写代码时需要知道的信息**。

## 写作红线

以下内容**禁止写入** AGENTS.md：

- **Agent 能自行推断的常识**：标准工具默认用法、框架基本 API 用法（如 `useState` 怎么用）
- **与工具配置重复/冲突的规则**：已有 eslint/tsconfig 约束的不要重写
- **过时信息**：陈旧上下文比没有上下文更糟，Agent 会自信引用不存在的路径
- **模糊描述**：如"写好代码"、"注意性能" — 用可验证的具体规则替代
- **敏感信息**：密钥、内部地址、凭证

## 篇幅控制

- 单文件目标 **≤ 200 行**
- 超过时优先删减冗余，其次拆分为子目录 AGENTS.md
- 每条规则以「Agent 不遵守会怎样」为标准决定是否保留

## 核心工作流

### 第一步：读取现有 AGENTS.md

读取当前项目的 `AGENTS.md`，理解已有的内容结构和覆盖范围。

- **已有 AGENTS.md（完善流程）**：继续第二步
- **没有 AGENTS.md（新建流程）**：跳到「新建流程」

### 新建流程

1. **快速扫描**：项目根目录结构、`package.json`/`Cargo.toml`/`go.mod`/`pyproject.toml` 等包文件、技术栈识别
2. **产出骨架**：根据扫描结果，按 `references/section-guidelines.md` 中的章节模板生成初始 AGENTS.md 骨架（仅包含「环境与命令」「核心架构」「验证」等基础设施章节）
3. **深度探索**：进入第二步，补充「关键编码约定」「约束和禁止」等需要代码分析的章节

### 第二步：深度探索代码库

按照 `references/checklist.md` 中的探索清单，逐项分析项目代码实现，找出 AGENTS.md 中遗漏的编码约定和模式。

重点关注以下高价值区域（按项目类型取舍）：

1. **通知与反馈**：用户提示、日志输出、错误展示的统一方式
2. **API 数据转换**：枚举值、布尔值、时间格式等从 API 到业务层的转换约定
3. **模块间通信**：事件机制、依赖注入、消息队列等跨模块通信方式
4. **状态管理**：全局状态的读写方式、命名空间、跨模块访问规则
5. **国际化**：文案管理方式、key 命名规范、新增文案流程
6. **环境与配置**：环境判断方式、配置加载机制
7. **代码组织**：目录结构、文件放置规则、自动注册/发现机制
8. **数据库访问**（后端项目）：ORM 使用方式、事务管理、连接池
9. **配置管理**（后端项目）：环境变量加载、配置文件结构、敏感信息处理

### 第三步：对比与诊断

将探索发现与现有 AGENTS.md 对比，识别：

- **遗漏项**：代码中存在但 AGENTS.md 未记录的编码约定（按影响程度排序：高/中/低）
- **冗余项**：AGENTS.md 中记录但 Agent 开发时不需要操作的信息（如 CI 配置、构建基础设施、发布流程）
- **重复项**：多处描述同一件事的内容

### 第四步：输出诊断报告

向用户展示分析结果，格式如下：

```markdown
## 高概率踩坑（Agent 大概率会犯错）
1. [遗漏项] — 简要说明 Agent 会怎么写错 + 正确写法

## 可精简的内容
1. [冗余项] — 简要说明为什么 Agent 不需要知道这个

## 建议补充的内容
[精简后的新增内容]

## 潜在冲突
1. [冲突项] — AGENTS.md 描述与代码/工具配置不一致之处 + 建议处理方式
```

等待用户确认后再执行修改。

### 第五步：更新 AGENTS.md

根据用户确认的内容，按照 `references/section-guidelines.md` 中的章节规范，更新 AGENTS.md。

更新原则：

- **只加可操作的规则**，不加描述性的背景知识
- **每条规则必须能直接指导编码决策**
- 用代码示例而非纯文字描述约定
- 删除 Agent 不负责操作的信息（CI/CD、发布部署、构建基础设施细节）
- **验证章节优先局部校验**：区分可局部化的检查（lint/stylelint，给出单文件命令）和不可局部化的检查（类型检查等全量检查），后者改动后不强求执行、由 CI 兜底
- **关键编码约定必须包含 ✅/❌ 代码对比**，格式：`[约定名]：Agent 会用 {错误方式}，正确做法是 {正确方式}。原因：{为什么}`
- 建议在 AGENTS.md 末尾附加自校正条款：`若 AGENTS.md 描述与当前代码不一致，优先遵循代码，并提示用户更新本文件。`

## 章节结构参考

不同类型的项目需要不同的章节组合。完整的章节编写规范和模板见 `references/section-guidelines.md`。

常见章节（按需取舍）：

```markdown
# AGENTS.md — {项目名}
{一句话技术栈描述}

## 环境与命令
## 验证
## 核心架构
## 关键编码约定
## 代码风格
## 工程惯例
## 约束和禁止
## 验证清单
## 知识库
```

## 探索清单

完整的代码探索项见 `references/checklist.md`，按优先级分为：

- **P0 必查项**：遗漏后 Agent 一定会写错代码的约定
- **P1 建议查项**：遗漏后特定场景会踩坑的约定
- **P2 可选查项**：有助于理解但可通过读代码学到的信息

根据项目规模和可用时间，至少完成 P0 项的探索。
