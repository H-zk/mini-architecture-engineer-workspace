# 视图类交付先定 jobs-to-be-done

> 适用 = 给操作者产**视图类交付物**（看板 / 报告 / 仪表盘 / HTML 汇总页 / 图解页）的**设计冻结前**。判别：产出物是被「看」和「据此行动」的，不是被逐字读的。本文件管视图级设计门禁；单张图的模型选型走 SKILL §一（图级判据是本门禁的下游特例）。

## 门禁（设计冻结前逐条过）

1. **先写 jobs-to-be-done 清单，输出形态从 jobs 推导**：「操作者拿它做哪几个决定/动作」，一行一个；每个 job 在输出结构里有对应的结构位。判例：会话看板四件事——开工选择 / 全景地图 / 风险雷达 / 单卡接手——四段输出与之一一对应。
2. **jobs 写不出 = 需求还没清楚**：先问操作者拿它干什么，再动手设计；不用「先做一版看反馈」代替这一问。
3. **注意力友好 = 结构对齐，不靠压缩信息**：信息按使用场景排布——该扫的全量给全量、该决策的置顶、该追踪的按生命周期排、风险信号独立成段。

## 结构对齐的形态约定

- 全量表不压缩名单：禁砍行、禁把组压缩成斜杠名单（那是目录不是信息）。
- 置顶建议 2–3 条，每条带一句为什么；是建议不是结论，操作者可无视。
- 风险/异常信号独立成段，不混入常规列表。

## 检查清单

- [ ] jobs 清单写出来了吗（≥1 个具体动作，「了解现状」类含糊句不算）？
- [ ] 每个 job 在输出结构里有对应的结构位吗？
- [ ] 有没有以「注意力友好」为名删掉全量信息（简报化）？

> 同族信号纪律：交付简报化反馈出现第 2 次即触发本门禁复盘——同族信号记一处，不分散登记。
