# workspace-grills — 治理审计决策记录（冷层）

`workspace-grill` skill 落地完成的决策记录归档处（`grill-<日期>.md`），历次清单见下表。冷层属性：仅追溯时读；任何真源（含 CHANGELOG）不反向引用本目录内容（说明依据写「按 grill 决议实施」）。

## 为什么有这个目录

grill 通过 task 承载过程（task README 决议 + CURRENT 进度），但 grill 决策的历史需要独立冷层存档（task 归档后仍可独立追溯，不依赖 task 存活）。与 [`retrospectives/`](../retrospectives/README.md)（回顾历史）对仗；grill 的**机制**（三模式、门禁、BACKLOG 清理）见 [`workspace-grill` skill](../.agents/skills/workspace-grill/SKILL.md)，本目录只存**历史决策**。

## 单份结构契约（决策记录形态，~30-60 行）

归档件**是决策记录，不是规格草稿**——规格归 skill / task README，这里只留「决定了什么、落没落、预期怎么验」：

1. **标题**：`# grill-<日期>：<主题>（<模式>）`
2. **决议**：操作者确认日期 + 采纳范围（全采纳/部分采纳注明取舍）——逐条可执行结论
3. **证据要点**：只留支撑决议的关键证据行，全表以指针引 task README（不复制）
4. **落地表**：决议 → 落地动作 → 完成状态（同日完成的注明；跨日的记 task 指针）
5. **预期**：转正/复查判据（何时回看、看什么信号）
6. **附**（可选）：会话教训 → exps 指针

> 反形态警示：回退成「背景分析 + 方案论证 + 待办清单」的规格草稿形态 = 契约违背——那是 task 阶段产物，归档件只认决策记录形态。

同日多轮 grill：标题日期 token 加「（第 N 轮）」后缀（`# grill-<日期>（第二轮）：…`），以 `---` 分隔追加到当日归档件（首轮 H1 不动）；清单表加一行、日期列带轮次、文件列注明轮次节。
