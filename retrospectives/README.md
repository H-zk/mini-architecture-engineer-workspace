# 阶段回顾（retrospectives）

迭代末的**执行质量复盘**，硬锚点 = 迭代末（sprint 发布后）。发 `#workspace-optimize 做一次阶段回顾` 触发。

## 方法

回顾是**开放式深度分析，不是固定 skill 流程**：锚定上一次回顾的 commit 到当前 HEAD，深度复盘「执行质量」（做对 / 做快 / 做扎实），分「做对了什么 / 还不够好 / 能力自评」**带证据**分析（引用任务 CURRENT 历史、返工/纠正记录、git log），产出 `retrospectives/retro-YYYY-MM-DD.md`。

回顾同时完成五件机制闭环：

1. **定下迭代参数**：确定下个 `sprint-version` + 周期，写入本文件「节点锚」；
2. **归档批次**：本迭代任务（grep `sprint-version: <本轮>`，含已完成待归档的）统一移入各根目录 `archive/`（归档硬截止：此后不再 reopen）；
3. **毕业清单确认**：`exps/INDEX.md` 标了「毕业候选」的条目逐条裁决（去向见 WORKFLOW §2.4「经验三级与毕业」）；
4. **待对账打捞**：grep `待对账:` 捞到的事项建新任务关联原任务处理；
5. **定期项节奏核对**：预配置学习源（若有）的增量锚点有无落后、未裁决轮次有无积压——有则当场立学习任务（学习源非周期、按提醒触发；口径与锚点见 [position/](../position/README.md) 登记表）。

产物为 BACKLOG / WORKFLOW 调整提供基于事实的输入，但遵循「宁可晚进」——回顾只产候选，不直接改机制。
