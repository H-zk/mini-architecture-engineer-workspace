# 阶段回顾（retrospectives/）

> 本目录存档工作区的**定期回顾**——锚定上一个回顾节点到当前 HEAD，按**七层清算**承前启后（v2：position 定位基准起步、逐层向下、治理冷层收口，层表见 B 段第 11 步）。定位**冷层**（仅回顾时读，不进每次会话热层），与 `CHANGELOG.md`（变更日志）互补：CHANGELOG 记「改了什么」，retrospectives 记「改得怎么样、方向对不对」。
>
> **template 线按需执行、不锚定迭代末**（迭代机制与试行态同口径对外提供，见 [WORKFLOW §2.7](../WORKFLOW.md) 豁免）——本 README 按 受让方实战口径描述全流程；template 线发起时按需裁剪（A 段照走、B 段按需深浅）。发 `#workspace-optimize 做一次阶段回顾` 触发。

## 为什么有这个机制

架构师不能脱离开发职责空谈架构——**先把需求做对做快、把 CASE 修准，是地基；架构健康视角是叠在地基上的，不是替代地基**。定期回顾是为了：

1. 让「执行质量」被**周期性**审视，而非只在踩坑时被动反思；
2. 留下**可追溯的演进轨迹**（每次锚定 commit 范围），看清工作区是在变好还是变臃肿；
3. 为 BACKLOG 升级 / WORKFLOW 调整提供**基于事实的**输入（而非凭感觉），呼应「宁可晚进，不早进」。

## 怎么做一次回顾（两段式：A 段必走，B 段按需深浅）

> **原则**：A 段是迭代末硬锚点，**不可省略**；B 段深度由本迭代信号定——任务少 / 无异常一眼带过，出现返工模式 / 跨迭代趋势才深挖。回顾步骤与治理批次各阶段由本次回顾圈定范围选用，**不必全走**。

### A 段 · 迭代收尾必走（硬锚点）

> **结束批（迭代结束态）= 回顾启动 → tag**（状态机见 [WORKFLOW §2.7](../WORKFLOW.md)）：回顾裁决事项**销账（零悬空）** + 收口清单（下方 1-8 步）**收完才走第 9 步打 tag** + commit 按主题聚批——执行流单一真源 = [`sprint-iteration`](../.agents/skills/sprint-iteration/SKILL.md) skill。

1. **锚定范围**：① **commit 范围**——从下方[节点锚](#节点锚)取上次回顾的 `to-commit` → 当前 HEAD（首次从工作区起点）；② **任务范围**——`grep "sprint-version: <本轮>"` 拿本迭代的业务任务（**它们完成后留活跃区、尚未归档**，待本轮评分；见 WORKFLOW §2.7）；顺带列**掉落榜**——本迭代含 `sprint-log` 的任务一行一档（轨迹 + 跨几轮），掉落规模一眼可见。
2. **钩子打捞（待对账 + 定期项节奏核对）**：`grep "待对账"` 跨任务目录捞已完成任务里标记的待对账事项，对到期的（修复一般 1-2 迭代上线）**建立新任务**关联原任务处理（交叉验证 → 回写 `notes/`）——这取代「让原任务挂中间态」（机制见 [WORKFLOW §2.6](../WORKFLOW.md)「待对账钩子」）；同场核对定期项——预配置学习源（若有）的增量锚点有无落后、未裁决轮次有无积压，有则当场立学习任务（学习源非周期、按提醒触发；口径与锚点见 [position/](../position/README.md) 的 colleague / open-source 登记表，学习源登记位随首个学习源建立）。
3. **exps 毕业清单确认**：数据源 = [`exps/TRIGGERS.md`](../exps/TRIGGERS.md) 台账——过一遍确认计数（≥2 该标候选、≥3 必毕业）与疑似待复核行（当场判同类：确认 / 剔除），对账 `exps/INDEX.md` 毕业标记列；AI 提议（候选 + 去向）、操作者确认执行（触发 = 再犯与双通道机制见 [WORKFLOW §2.4](../WORKFLOW.md)「经验三级与毕业」；即时通道随任务收尾发生，不在此重复）。
4. **成熟度盘点（收口，声明制）**：对**累积试行清单**按证据收口——遍历 CHANGELOG 中标「试行」且尚未判定的机制，逐条判定：**定型**（本迭代 ≥1 个真实任务用过 + 无未决问题 / 返工信号 → 毕业）/ **继续试行**（尚无使用证据）/ **退役**（失效或被取代，交第 5 步清扫移除）。产出「定型/试行清单」落入本迭代 CHANGELOG 条目（声明在机制落地时已前置，本步只收口）。
5. **清扫（废弃文案 + 溯源注记 + 隐性残余，三件同批）**：
   - **废弃文案**：移除历次修改残留——旧名词残留（改名后旧标识符）、被取代的规则句、指向已删机制的失联指针。方法：grep 旧词族 + 走查本迭代 CHANGELOG 涉及文件；`workspace-check` 既有链接 / 旧状态名检查作机械兜底。
   - **溯源注记**：扫**机制层**（自有 skills 含 references/scripts、顶层机制文档、各 INDEX/README 规则行）规则句上的溯源注记——日期标记、落地来源（B 编号并入 / 毕业落地 / 操作者裁定 / 固化 / 追认）、先例与改名史叙述；**规则本体保留、只摘注记**，让工作区以稳定形态进入下迭代。迭代期允许注记（辅助 review 与当场追溯）；tag 即确认，注记溯源下沉 CHANGELOG 与 git——回溯三通道：CHANGELOG 逐任务条目 / `git log -S` / 任务目录（含 `archive/<根>/`）。保留例外：活口径日期（被规则或机器校验引用的截止日）、活状态限定（【试行】/ 试点观察——归第 4 步收口）、命名示例与模板占位、frontmatter 元数据、vendor skill 本体、账本类载体（CHANGELOG / ARCHITECTURE 评分账〔§3/§4 按迭代迁 `archive/architecture/`，见第 8 步〕/ BACKLOG / retrospectives / 任务目录 / exps / notes / INDEX 任务行）。召回 = grep 日期模式（如 `20\d\d-\d\d-\d\d`）+ 走查涉及文件，**逐处判断、不盲删**。
   - **隐性残余五形态**（瘦身保证，逐形态召回）：① 退役机制残余——从 CHANGELOG 反查「取代 / 退役 / 合并了原」提取词族，扫活文档残留；② 死指令族——候选毕业移出（BACKLOG 墓碑）时当场反查引用该编号的活 skill / 文档指令，迭代末兜底再扫；③ 归档断链——任务归档时当场反查活文档对该任务的路径引用（补 `archive/<根>/` 路径段），迭代末兜底再扫；④ 过时状态快照——具体候选 / 任务 / 机制的状态描述驻留非真源处且已变，更新为终态或抽象为通用句；⑤ 旧状态词 / 改名史——已废弃标识符（状态名 / 目录名 / 标签名）活文档清零（账本历史叙述保留）。
   - **软链核销**：扫活 skill 与顶层文档「下回合补做 / 首用时回写 / 待实际需求再定」类承诺，未执行且未裁决的当场执行或注销（非阻断提醒不靠自觉累积）。归档件冻结不动；账本类历史引用合法。
6. **回顾后归档（批次动作）**：本轮 sprint 的**所有已完成任务**（含 #workspace-optimize，无论是否参与评分；顺延任务未完成、不归档——由第 7 步定参时掉落改标，留活跃区待下轮清算）统一归档至根级 `archive/<根>/`（清理活跃区，下轮新任务标新 sprint-version；reopen 归档硬截止由此生效）；归档索引行随迁移写入 `archive/<根>/INDEX.md`，热层 INDEX 同步删行。**迭代期间任务完成后留活跃区、不立即归档**——归档是迭代的收尾批次动作，确保迭代期间活跃区 = 完整迭代范围（见 WORKFLOW §2.7）。
7. **定下迭代参数**：确定下个 `sprint-version` 与周期——**值写入 WORKFLOW frontmatter `sprint-version`（当前迭代唯一真源，任务立项与改标取值皆源于此）** + **顺延任务掉落改标**（执行真源 = sprint-iteration 结束批 / WORKFLOW §2.7 掉落改标），周期叙述写入本文件[节点锚](#节点锚)。
8. **产物落盘**：`retro-YYYY-MM-DD.md`（frontmatter 记 `from-commit` / `to-commit`；A 段为主时正文精简记录各锚点动作即可）；更新本文件[节点锚](#节点锚)（含本迭代稳定 tag）与[历次清单](#历次清单)；更新 [`../ARCHITECTURE.md`](../ARCHITECTURE.md) §4 的迭代评分快照（能力反馈评分挂本节奏，不新增独立节奏），同时把上一迭代的 §3 反馈行与被替换的 §4 快照迁 `archive/architecture/<迭代名>.md`（评分账热层只留当前迭代行 + 最新收敛快照，原样冻结不改写；归档根规则见 WORKFLOW §2.5）；产出**工作区分层快照** `../position/snapshots/snapshot-sprint-<本轮>.md`（迭代边界状态锚：固定七层结构 + 数据画像，模板 = [`snapshot-template.md`](./snapshot-template.md)；相邻快照章节级 diff + frontmatter commit 锚 = 快速版本差异分析）。
9. **打稳定 tag `sprint-<本轮>`（门禁制）**：打 tag 前先走**第三方观察**（回顾产物落盘后插入：评分证据复核 + BACKLOG 体检 + 追认类当迭代落地，产物随同批 commit——时序「观察 → commit → tag」；观察机制未建仓的按此三件轻量执行）；tag 七门禁与操作细则（annotated / message / push refspec / 操作者独立发起）单一真源 = [`sprint-iteration`](../.agents/skills/sprint-iteration/SKILL.md) skill。用途：跨周期信任根锚 + 外部学习线锚定「最近稳定 tag」（定型清单直接借鉴；试行项跳过、转定型后随未来 tag 重现）。

### B 段 · 深度复盘（按需深浅）

10. **数据概览**：`git log --oneline <from>..HEAD`、`git diff --shortstat <from>..HEAD>`、WORKFLOW `version` 变化、各根目录任务 / exps / notes / skill 数量变化、`workspace-check` errors/warnings 趋势。
11. **深度分析（v2 七层清算）**：按层递进、每层固定两问——承前（验证 / 偏移了什么）+ 启后（交出什么、下迭代聚焦什么）。层序与检核面 = 分层快照「七层全景模型」（[snapshot-template.md](./snapshot-template.md)，相邻快照 diff 即逐层承前启后的对照基础）：

    - **① 定位层 position**：对照 position 各节（我是谁 / 初心 / 不变原则 / 边界）逐项检核，偏移先记信号再谈归因（如「业务 > 治理」占比偏移）。
    - **② 顶层文档层**（README / HUMAN / AGENTS / WORKFLOW + ARCHITECTURE 评分账 + BACKLOG 债账 + CHANGELOG）：单一真源守住否；评分账健康度（体系碎片化 / 口径统一 / 趋势）；BACKLOG 流入流出与护栏执行；HUMAN 随机制同步否。
    - **③ 能力层**（skills / commands / .tools / 配置）：能力账（新增 / 毕业 / 定型 / 缺口）+ 形态判据视角（哪些机制本迭代从「靠自觉」迁入「靠强制」；成熟度盘点作输入）。
    - **④ 任务层**：数据概览（第 10 步）+ **做对了什么 / 还不够好 / 能力自评（强势 + 薄弱）**（带证据可查）。
    - **⑤ 知识层**（exps / notes / reference）：消费与膨胀——漏命中率 / 未查率 / 超长行回弹 / 检索面健康。
    - **⑥ 代码层 src/**（浅检）：worktree 卫生 / 基础副本只读纪律 / 长线收口位。
    - **⑦ 治理冷层**（retrospectives / workspace-grills / 第三方观察）：清算产物完整性；观察机制运行与消费。
12. **给下一周期的输入**：可落地的优先级建议——**只产新候选进 `BACKLOG.md`**，不评估既有候选（既有候选的评估消费收敛为 workspace-grill 单一评估者 + 同事库对比重评，见 `workspace-grill` skill 与 `workspace-ops` skill 分工），且**遵循「宁可晚进」**——回顾产出的是判断，不是立即生效的机制。

## 新迭代开始批（迭代开始态：tag 后 → 手册确认 + review 推送）

tag 落地即进入（物证推断，无需显式发起），流程链 = 遗留裁决门（清单与开启手册草案同场呈报）→ 按裁决回补白名单待办 → 开启手册定稿 → 操作者确认（确认闸门）→ 任务收尾 → review 提交推送（新迭代开始物证）——执行流单一真源 = [`sprint-iteration`](../.agents/skills/sprint-iteration/SKILL.md) skill。

## 触发

操作者在**每迭代末（sprint 发布版本发布后）**发 **`#workspace-optimize 做一次阶段回顾`**，AI 按本 README 方法执行（迭代节奏见 [WORKFLOW §2.7](../WORKFLOW.md)）。回顾本身是开放式深度分析，**不做成固定 skill 流程**（避免过早固化、精致空转）；回顾后确定下个 sprint-version 与周期。

**大量级的启动措施（分批打法）**：任务量大到单会话处理不过来（参考线 >50 任务）时，先走一轮回顾前置预备——**规模盘点 → 主题分组 → 点名议程收集 → 执行计划 → 立项分批执行**五步——预备是把回顾**分批可执行化**（回顾本体的开放式深度分析定位不变）；分批执行形态 = 系列任务模式（阶段 = 节奏与交付单元，真源 = sprint-iteration skill 结束批节）。
